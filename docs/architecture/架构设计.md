# ClipboardBoard 架构设计

## 目标与边界

本架构服务于 Windows 10/11 x64 本地剪贴板工具。目标是低待机资源、快速面板呼出、文本和图片可靠持久化，以及不会因权限或敏感内容处理而产生错误自动粘贴或隐私泄漏。

非目标：云服务、远端 API、账号系统、跨设备同步和富文本完整还原。

## 组件职责

| 组件 | 责任 | 禁止事项 |
|---|---|---|
| Slint UI | 渲染、键盘交互、窗口状态和 UI 模型 | 直接访问 SQLite、阻塞文件 IO、跨线程修改模型 |
| Win32 消息窗口 | 热键、托盘、剪贴板更新、单实例消息 | 读取正文、图片解析、SQLite 写入 |
| ClipboardIoWorker | 打开剪贴板、复制自有数据、写回系统剪贴板 | 创建 Slint Image、压缩图片、持久化 SQLite |
| ImageWorker | 解码、规范化、PNG/WebP 编码、图片文件发布 | 持有剪贴板句柄、修改 UI、创建 Slint Image |
| StorageExecutor | 唯一 SQLite 连接、迁移、CRUD、搜索和清理 | 修改 UI、直接调用 Win32 窗口 API |
| SettingsWorker | 读取和原子保存 settings.json | 修改 UI、直接重绑热键 |

## 线程与事件流

```text
WM_CLIPBOARDUPDATE
  → 消息窗口记录 sequence 和来源快照
  → 有界 latest-wins 队列
  → ClipboardIoWorker 读取并再次核对 sequence
  → 文本直接送 StorageExecutor / 图片送 ImageWorker
  → StorageExecutor 事务提交
  → UiEvent
  → Slint UI 更新摘要模型
```

所有非 UI 线程通过 `UiEvent` 和 `slint::invoke_from_event_loop` 返回结果。Slint `Image` 仅在 UI 线程创建。

## 数据模型

### SQLite

v1 保存文本历史：

- `id`。
- `item_type`。
- `text_content`。
- `preview_text`。
- `content_hash`。
- `source_exe`、`source_app`。
- `copy_count`、`is_pinned`。
- `created_at`、`copied_at`、`last_used_at`。

v2 增加图片元数据：

- `image_path`。
- `thumbnail_path`。
- `image_width`、`image_height`。
- `image_format`。
- `content_size`。

查询稳定排序为 `copied_at DESC, id DESC`，分页使用复合游标，不使用大 OFFSET。

### 图片资产

```text
%LOCALAPPDATA%\ClipboardBoard\
├── data\clipboard.db
├── images\
│   ├── original\<哈希前缀>\<哈希>.png
│   ├── thumbnail\<哈希前缀>\<哈希>.webp
│   ├── staging\
│   └── recovery\<时间戳>\
├── config\settings.json
└── logs\
```

原图 PNG 是耐久 payload；缩略图 WebP 是可重建缓存。图片文件先在 staging 写入、flush、关闭、原子发布和验证，再写入 SQLite 记录。

## 关键一致性规则

### 自身剪贴板写回

写回前登记规范哈希和格式集合；写回后记录精确 clipboard sequence。监听器只消费精确匹配的一次事件，超时或 sequence 越过后失效。这样重新复制历史不会增加 `copy_count` 或改变排序。

### 图片哈希

对解码后的顶向下、行连续 RGBA8 像素计算 BLAKE3，输入包含域标签、宽度、高度和像素。PNG、DIB、DIBV5 相同像素内容应合并为同一记录。

### 记录可见性

SQLite 是记录元数据真相源。文本与图片都必须在存储事务成功后才更新 UI。图片若文件发布失败或数据库事务失败，不得产生可见记录。

### 删除与对账

删除记录后由 StorageExecutor 提供已提交删除结果，再异步执行二次引用检查和文件回收。对账任务排除 staging、in-flight 和 recovery，且不得在数据库损坏恢复后清理旧资产根。

## 权限与隐私

- 高完整性目标窗口只允许“仅复制”，不调用 `SendInput`。
- 面板激活前记录原目标窗口；粘贴时只复核该目标，绝不向新前台窗口重试。
- 暂停与排除程序在 ClipboardIoWorker 读取正文前检查。
- 日志不记录正文、图片字节或默认窗口标题。

## 性能策略

- 启动只加载100条摘要，UI 首批30条。
- 后续每页50条。
- 文本与混合图片列表均在 Release 模式建立性能门禁。
- 固定高度卡片、缩略图延迟加载、可见区上下各10条 LRU。
- 不轮询；清理仅在启动完成、插入或配置变更后触发。

## 恢复与回滚

- 数据库损坏时停止工作线程，将数据库和当前图片资产根整体移入 recovery 包。
- 新库使用新的图片资产根，旧 recovery 包不参与自动对账或清理。
- 单原子验证失败时不提交；已提交原子可独立回退。
