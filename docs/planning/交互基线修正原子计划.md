## 一、交付单元

### 产品结果

把当前偏键盘命令面板的文本试用版修正为鼠标优先、显式复制、持续置顶的剪贴板看板：

- `Alt + V` 首次显示或重新激活面板，不再切换隐藏。
- 面板保持 Windows 始终置顶，点击其他应用不会自动隐藏。
- 用户主动按 `Esc` 才把面板隐藏到系统托盘；托盘“退出”仍结束进程。
- 鼠标点击卡片是主要选择方式，每张卡片提供明确的“复制”按钮。
- 应用只把内容写入系统剪贴板，不再模拟 `Ctrl + V` 或注入其他键盘输入。
- 只保留 `↑`、`↓` 作为辅助快捷键；普通 `Enter` 和 `Ctrl + Enter` 均不执行复制或粘贴。
- 历史首批从 SQLite 查询 30 条，滚动接近底部时每批继续加载 50 条。

### 验收场景

| 场景 | 可观察结果 |
|---|---|
| `SC-01` 面板驻留 | 打开面板后点击任意其他普通应用，面板仍可见且位于其上方；搜索和选择状态不被重置。 |
| `SC-02` 主动隐藏 | 面板内部任意焦点状态下按 `Esc` 都隐藏到托盘；重复 `Alt + V`、失焦、标题栏关闭请求和 `Alt + F4` 均不隐藏。 |
| `SC-03` 鼠标选择 | 点击一张卡片后该卡片出现明确选中态；迟到点击不能改变下一次面板会话。 |
| `SC-04` 显式复制 | 点击某卡片的“复制”按钮后，切换到目标应用并手动按 `Ctrl + V` 能得到精确正文；面板不自动关闭。 |
| `SC-05` 禁止自动输入 | 普通 `Enter` 不触发动作，生产代码不存在 `SendInput` 自动粘贴路径。 |
| `SC-06` 首批与分页 | 预置 85 条唯一文本时，首次取得 30 条，继续滚动依次追加 50 条和 5 条，无重复、遗漏或顺序跳变。 |
| `SC-07` 搜索竞态 | 快速输入新关键词、复制新内容或关闭面板后，旧首页和旧分页结果均不能覆盖当前列表。 |
| `SC-08` 隐私与写回 | UI DTO 和诊断日志不包含完整正文；应用自身写回仍按内容哈希和剪贴板 sequence 精确抑制一次。 |

### 明确排除

- 不实现收藏切换；继续由 `ATOM-26` 负责。
- 不实现图片捕获、图片筛选、缩略图或图片复制。
- 不实现删除、清空、暂停、排除程序、设置、开机启动或热键修改。
- 不增加复制成功 toast；失败只写固定诊断，不泄露正文。
- 不实现窗口缩放、拖动、可切换固定模式或取消置顶模式。
- 不改变 `Alt + V` 组合键。
- 不把完整正文放入 UI 卡片、搜索结果或日志。

## 二、现状证据

### 已确认行为

- `ui/app-window.slint` 的外层 `FocusScope` 在 `focus-lost` 时无条件发出关闭请求；普通 `Enter` 当前发出自动粘贴请求。
- `src/app/ui_event.rs` 中 `UiEvent::OpenPanel` 在面板已显示时返回隐藏动作；卡片模型被 `take(UI_FIRST_BATCH_SIZE)` 固定截断为 30 条。
- `src/platform/windows/window/lifecycle.rs` 的 `move_panel` 使用 `SWP_NOZORDER`，不会把 HWND 设置为 `HWND_TOPMOST`；同文件还包含 `SendInput` 自动粘贴实现。
- `src/storage/worker.rs` 已有 `HistoryQuery`、复合 `HistoryCursor` 和 `HistoryPage`，但 `HistorySummary` 尚未携带内容哈希。
- `StorageExecutor` 当前不可克隆，并被 `src/main.rs` 移交给单一 capture pump；UI 搜索只过滤容量为 100 的 `MemoryHistory`。
- Slint `ListView` 已通过 20,000 条窗口化结构探针，但真实桌面鼠标滚轮、首批 30 条后的 SQLite 续页尚未接线。
- 基线回归为 145 个测试通过，`origin/main` 与本地 `main` 均位于 `99c45d7`。

### 已确认缺陷

- 真实桌面点击面板内部会出现 `OpenPanel → focus-lost → HidePanel`，导致窗口立即隐藏。
- 用户已观察到面板可能处于其他窗口下方。
- 用户无法通过当前 UI 验证第 31 条及后续历史。

## 三、全局约束

### 产品与交互

1. 面板只有捕获阶段处理的 `Esc` 可以隐藏；托盘“退出”是结束进程，不属于隐藏。
2. `Alt + V` 和托盘“打开”在已显示时只重新显示、激活和断言置顶，不改变面板 generation、搜索文本、筛选、选择或分页状态。
3. 标题栏关闭请求和 `Alt + F4` 返回 `KeepWindowShown`，不得绕过 `Esc` 关闭协议。
4. 点击其他应用只改变输入焦点，不能改变面板可见状态。
5. 鼠标是复制操作的唯一入口；键盘只保留上下选择和 `Esc` 隐藏，不提供复制或粘贴快捷键。
6. 复制成功或失败都不自动隐藏面板；用户自行切换目标并按 `Ctrl + V`。
7. 生产路径不得调用 `SendInput`、模拟 `Ctrl + V` 或保存待粘贴目标窗口。

### 线程、队列与生命周期

1. Slint UI 只能在事件循环线程修改；UI 回调不得同步访问 SQLite、完整正文或 Windows 剪贴板。
2. UI 到后台的复制、搜索和分页请求必须非阻塞且有界。
3. SQLite 连接仍只有一个，始终由 storage worker 独占。
4. `StorageClient` 的克隆不拥有关闭权；owner 通过共享状态线性化 `Open → Closing → Closed`。
5. `begin_closing` 必须先建立关闭门禁，再等待 capture/query 线程退出；`finish_shutdown` 最后发送唯一 Shutdown 并 join SQLite worker。
6. 查询请求使用 latest-slot；结果 slot 与 wake-pending 必须处于同一互斥状态，禁止丢唤醒。
7. 所有查询响应都回显数据集 generation、请求 token 和请求 cursor；三者必须与活动请求精确一致。
8. 新搜索、新复制、`Esc` 隐藏以及后续收藏/删除变更都必须先使旧分页 token 失效。

### 数据与隐私

1. SQLite 排序保持 `copied_at DESC, id DESC`，分页继续使用复合游标，不使用 `OFFSET`。
2. 首页固定 30 条，后续通常 50 条；接近 2,000 条上限时请求量取剩余数量。
3. `HistorySummary` 可携带严格 32 字节内容哈希，但不得携带 `text_content`。
4. 复制前后台继续按 ID 读取完整 payload，校验类型、内部 NUL、哈希长度和正文重算哈希。
5. 应用自身写回继续使用 token、内容哈希、格式和精确 clipboard sequence 抑制一次捕获。
6. 诊断日志不得记录正文、搜索结果正文、窗口标题或原生错误详情。

### 仓库与提交

1. 所有新增或修改的 Rust、Slint 和脚本代码必须同步维护中文文件级、公共接口和关键逻辑注释。
2. 同一时间只执行一个原子；每个原子独立验证、独立提交、独立推送。
3. 用户已授权按依赖顺序连续实现剩余原子，中间不因原子完成而暂停。
4. 远端目标沿用已授权的 `origin/main`；禁止强制推送。

### 验证与复核

1. 不运行 `cargo test --all-targets` 或其他全量测试；每个原子只运行覆盖本次改动路径的定向测试、必要编译检查和格式检查。
2. 定向测试验证可执行行为，DDD 复核验证测试难以直接证明的竞态、生命周期和跨模块不变量；两者互补，不互相替代。
3. 涉及原生窗口、置顶或滚动交互的原子补最小 Windows 桌面冒烟，不扩大到无关功能。
4. 若验证失败，只修复并重跑受影响的定向测试；每个原子仍须在独立验证、DDD 门禁和差异检查通过后提交。

## WCB-INT-01 固定面板级键盘契约

- 状态：`done`
- 支持的验收场景：`SC-02`、`SC-05`
- 唯一目标：在任意现有内部焦点下，`Esc` 可靠隐藏，普通 `Enter` 和 `Ctrl + Enter` 均不触发复制或粘贴。
- 当前行为与目标行为：当前外层 `key-pressed` 可能收不到被 `LineEdit` 消费的键，普通 `Enter` 会启动自动粘贴，`Ctrl + Enter` 会复制；完成后使用捕获阶段统一处理面板级按键并删除两个 Enter 回调入口。
- 前置条件与依赖：基线 145 个测试通过。
- 代码定位依据：`ui/app-window.slint` 的 `FocusScope.key-pressed`、`copy-selection-requested` 和 `paste-selection-requested`；`src/app/ui_event.rs` 的两个窗口回调绑定。
- 允许修改：上述 UI/回调绑定文件、直接键盘交互测试，以及受新产品决定影响的计划与产品文档。
- 明确不修改：不删除底层 Paste 类型，不改窗口置顶、失焦、鼠标卡片、分页或 SQLite。
- 实现步骤：
  1. 把面板级快捷键切到包围全部现有控件的 `capture-key-pressed` 阶段。
  2. `Esc` 生成当前 `panel_generation` 的 `HidePanel`。
  3. 捕获阶段对任意修饰键组合的 `Key.Return` 返回 `accept`，不发送复制或粘贴事件。
  4. 删除 Slint 的复制/粘贴 Enter 回调以及 Rust 窗口绑定，使两个入口在类型层面不可调用。
  5. 保留上下键辅助选择，并把底部提示改为只展示“↑↓ 选择、Esc 关闭”。
- 接口、数据与错误契约：本原子不新增复制 DTO；既有后台复制和自动粘贴基础设施暂不删除，但 UI 不再有键盘入口。
- 边界与异常：搜索框、卡片或未来按钮持有焦点时，Enter 组合都必须被面板捕获并静默消费，不能触发子控件默认提交。
- 测试要求：
  - 搜索框持有焦点时 `Esc` 仍隐藏。
  - 搜索框持有焦点时普通 `Enter` 与 `Ctrl + Enter` 都不产生复制或粘贴回调。
  - Slint 生成 API 不再包含两个 Enter 回调绑定。
  - 上下键选择行为保持不变。
- 验证命令：键盘交互集成测试；`cargo test --locked app::ui_event`；`cargo test --all-targets --locked`；`cargo fmt --all -- --check`。
- 预期结果：键盘契约可重复测试，尚未删除的底层复制和自动粘贴代码均不可由 UI 键盘到达。
- 完成判定：Esc 对搜索框焦点可靠，Enter 与 Ctrl+Enter 无用户可达动作，仓库通过相关测试。
- 交付给下一原子的输出：自动粘贴类型和 Win32 输入注入成为不可达代码，可安全删除；显式复制入口只由 WCB-INT-06 的鼠标按钮重新接入。
- 停止或重新规划条件：Slint 当前版本没有可覆盖内部控件的捕获阶段；必须先用最小测试确认替代事件传播方案。
- 风险等级：L2
- DDD 门禁：提交前审查键盘捕获、子控件默认行为和复制/粘贴入口可达性，必须为 `PASS`。
- 计划提交信息：`fix(interaction): [WCB-INT-01] 固定面板级键盘契约`

- 代码定位依据：`src/storage/worker.rs` 的 `StorageExecutor`、容量 4 `sync_channel` 和 Shutdown；`src/main.rs` 的启动恢复、capture pump 所有权和退出顺序。
- 允许修改：storage owner/client、调用方签名、main 生命周期和存储/关闭测试。
- 明确不修改：不增加第二个 SQLite 连接，不接 UI 查询，不改变 SQL、schema 或业务排序。
- 实现步骤：
  1. owner 和 client 共享 `Open/Closing/Closed` 状态及提交互斥门禁。
  2. client 可克隆，但没有 shutdown/join API；提交在门禁内确认 Open 后进入现有容量 4 队列。
  3. 业务输入关闭后立即调用 `begin_closing`，在门禁内进入 Closing，使所有新提交和逃逸 clone 固定失败。
  4. 已经入队的命令允许完成；capture/query 线程随后退出并 join。
  5. `finish_shutdown` 由 owner 绕过 client 门禁发送唯一 Shutdown，等待回执并 join SQLite worker，最后进入 Closed。
  6. UI 线程永远不直接调用同步 client 方法。
- 接口、数据与错误契约：Closing/Closed 提交返回稳定 `StorageError`；一个 owner 只允许一次 begin/finish；Drop 保持保守关闭。
- 边界与异常：满队列、正在等待回执、逃逸 clone 持续提交、worker panic 和重复关闭都不能死锁。
- 测试要求：
  - 两个客户端的命令仍在同一 connection thread 执行。
  - 持续提交 clone 与 `begin_closing` 并发时最终线性化，Closing 后立即拒绝。
  - 满队列和 shutdown 竞争不死锁。
  - 已入队命令完成后唯一 Shutdown/join。
  - 关闭后所有 clone 返回固定错误。
- 验证命令：`storage::worker` 生命周期、并发提交和关闭竞态定向测试；Windows Debug check。
- 预期结果：多个后台工作线程可共享存储命令协议，SQLite 连接仍唯一且关闭可证明。
- 完成判定：并发、满队列、逃逸 clone 和单连接测试全部通过。
- 交付给下一原子的输出：history query worker 可持有独立 `StorageClient`，main 仍控制唯一关闭顺序。
- 停止或重新规划条件：无法在线性化门禁内避免 shutdown 死锁；必须重新设计命令所有权，不能用第二连接绕过。

## WCB-INT-09 接入 SQLite 首批搜索

- 状态：`pending`
- 支持的验收场景：`SC-06`、`SC-07`、`SC-08`
- 唯一目标：打开面板或搜索防抖到期后，异步从 SQLite 获取当前筛选的首批 30 条并安全替换列表。
- 当前行为与目标行为：当前搜索只过滤 100 条内存摘要；完成后 SQLite 是首批结果真相源，UI 不阻塞查询。
- 前置条件与依赖：`WCB-INT-08` 提供可在线程中使用的 `StorageClient`。
- 代码定位依据：`src/search/mod.rs` 的防抖 generation；`src/app/ui_event.rs` 的内存过滤；`src/storage/worker.rs` 的 `query_history_summaries`；`src/main.rs` 的工作线程启动/退出。
- 允许修改：新增历史查询 worker/邮箱、搜索协调器、UI 首批结果事件、main wiring 和相关测试。
- 明确不修改：不实现 load-more、收藏写回、图片、删除或 UI 正文加载。
- 实现步骤：
  1. 建立请求 latest-slot：UI 在互斥槽覆盖最新请求并非阻塞唤醒 worker。
  2. 建立结果 latest-slot：slot 与 `wake_pending` 处于同一互斥状态；producer 只在 `false → true` 时投递一个 UI wake，UI 在同一临界区取结果并清 pending。
  3. 把搜索数据集 generation 与单次 request token 分开；每个响应回显 `(generation, token, requested_cursor=None)`。
  4. `SearchCoordinator` 只负责 120ms 防抖；首批接受由 `HistoryPageCoordinator` 精确校验可见性和三元身份。
  5. 面板首次打开和搜索/筛选变化派发 `limit=30`、空 cursor 查询；loading 保留旧卡片。
  6. 捕获事务提交成功且面板可见时立即分配新 generation，先使所有旧 token 失效，再刷新当前首页。
  7. 首批失败保留旧卡片并显示固定错误；错误不携带正文或 SQLite 细节。
  8. 旧卡片交互继续只用 `(panel_generation,id,hash)`，不把 search generation 混入复制身份。
- 接口、数据与错误契约：UI wake 事件不携带正文；结果只含 `HistorySummary` 转换的轻量 DTO、next cursor 和有限错误类别。
- 边界与异常：
  - worker 在 UI 取空后写结果时必须重新唤醒，不能丢结果。
  - 旧查询 Q 先于 upsert U 执行、但 Q 的 UI 回调后到时，必须因 capture 新 generation 被拒绝。
  - loading 期间点击旧卡片仍复制旧卡片身份；结果替换后按 ID/hash 重定位或清空选择。
- 测试要求：
  - UI 提交在请求槽繁忙时立即返回且最终 worker 只处理最新请求。
  - 结果 slot 读空/写入边界无丢唤醒。
  - 旧 generation、错误 token 或非空 cursor 的首页响应被拒绝。
  - 快速搜索只显示最终关键词结果。
  - Q/U 乱序确定性测试拒绝陈旧首页。
  - 预置超过 100 条时可搜索到内存缓存之外记录。
  - 查询失败保留旧卡片并显示固定错误。
- 验证命令：相关 search/history query/UI 首页定向测试；`cargo check --lib --locked`；Windows Debug check。
- 预期结果：搜索和面板首页来自 SQLite，120ms 防抖、迟到隔离和 UI 非阻塞同时成立。
- 完成判定：有界请求/结果邮箱、精确身份和内存外搜索测试全部通过。
- 交付给下一原子的输出：UI 状态持有活动 generation、首页 request token、已加载 30 条和 `next_cursor`。
- 停止或重新规划条件：Slint wake 无法与结果 slot 建立无丢失协议；必须先用确定性测试修正邮箱，不得改用 UI 同步查询。
- 风险等级：L3
- DDD 门禁：编码前与提交前强制审查邮箱、generation/token/cursor 和捕获竞态，必须为 `PASS`。
- 计划提交信息：`feat(search): [WCB-INT-09] 接入 SQLite 首批查询`

## WCB-INT-10 接入滚动续页

- 状态：`pending`
- 支持的验收场景：`SC-06`、`SC-07`
- 唯一目标：鼠标滚动接近列表底部时，按当前筛选的复合游标继续加载后续摘要。
- 当前行为与目标行为：当前窗口模型固定 30 条且没有 load-more；完成后首批 30、后续 50，最多加载 2,000 条摘要。
- 前置条件与依赖：`WCB-INT-09` 已建立活动数据集、首批结果和双向有界查询邮箱。
- 代码定位依据：`ui/app-window.slint` 的 `ListView/viewport-y`；`src/app/ui_event.rs` 的 30 条截断和 selection limit；`HistoryPage.next_cursor`。
- 允许修改：分页协调器、ListView 底部触发、追加模型、加载失败重试 UI 和直接测试。
- 明确不修改：不实现图片懒加载、收藏/删除、历史清理或传统页码。
- 实现步骤：
  1. 当视口从非底部进入距底部两行范围时发出 load-more 请求。
  2. 请求和响应都携带 `(generation, request_token, requested_cursor)`；同一 generation 同时最多一个活动 token。
  3. 成功页按数据库顺序追加，按 ID 去重；只有成功且身份精确匹配时推进 cursor。
  4. 失败保留旧行和 cursor，进入 `retry_required`，显示固定“加载失败，点击重试”；普通重绘和重复 viewport 通知不得自动重试。
  5. 显式重试或用户先离开底部再重新进入底部边沿时分配新 token。
  6. 新搜索、新捕获和 `Esc` 先使活动 token 失效，再改变数据集或可见状态。
  7. 请求量为 `min(50, 2000 - loaded_count)`；达到 2,000 后清除可加载状态。
  8. selection limit 扩展为全部已加载摘要；窗口化 delegate 和完整正文隔离保持不变。
- 接口、数据与错误契约：cursor 只来自当前成功页；重试沿用同一 cursor 但必须使用新 token；错误文案固定且无正文。
- 边界与异常：
  - 迟到页不能追加到同 generation 的新首页或重试结果。
  - 捕获导致数据排序变化时必须通过新 generation 整体失效旧页。
  - 1980、1999、2000 和超过 2000 条时不得越过加载上限或跳过允许记录。
  - 去重不得改变剩余行的数据库顺序。
- 测试要求：
  - 85 条严格得到 30、50、5，ID 顺序完整且无重复。
  - 旧 token、错误 cursor、旧 generation 结果被拒绝。
  - 一次失败后重复布局通知不产生新请求；显式重试只产生一次。
  - 快速重复底部触发只有一个 in-flight。
  - 1980/1999/2000/2001 边界请求量和停止状态正确。
  - 鼠标选择和键盘选择可到达第 31 条及以后。
  - 20,000 条 ListView 窗口化性能探针继续通过。
- 验证命令：分页/UI 定向测试；`pwsh -NoProfile -File scripts/measure_list_performance.ps1`；Windows Release 构建；真实桌面鼠标滚轮验收。
- 预期结果：文本历史可通过鼠标连续浏览到加载上限，查询和 UI 模型保持有界、稳定、可重试。
- 完成判定：30+50+5、竞态、失败重试、2,000 边界、性能探针和真实滚轮全部通过。
- 交付给下一原子的输出：交互基线修正完成；`ATOM-26` 可在当前分页模型上实现收藏切换。
- 停止或重新规划条件：真实桌面滚轮无法驱动 Slint viewport；必须先拆分原生滚轮事件接缝，不得用测试属性写入冒充人工交互。
- 风险等级：L3
- DDD 门禁：编码前与提交前强制审查分页幂等、游标、重试和捕获顺序，必须为 `PASS`。
- 计划提交信息：`feat(history): [WCB-INT-10] 支持滚动加载后续历史`

## 七、计划质疑结果

- 风险分类：窗口生命周期、Win32 topmost、存储客户端、查询邮箱和分页状态均为 L2/L3。
- 第 1 轮：发现普通有界队列无法同时满足 latest-wins 与 UI 非阻塞、分页响应身份不足、StorageClient 关闭竞态、原生关闭请求遗漏、内部焦点快捷键不可靠等问题；结果为 `REPLAN_ATOMS`。
- 第 2 轮：补充共享关闭门禁、generation/token/cursor 三元接受、捕获失效、末页上限、稳定卡片身份、close-requested 和 Copy 队列不变量；仍发现丢唤醒、Closing 时机和失败重试风暴。
- 第 3 轮：把结果 slot 与 wake 标志放入同一锁，拆分 `begin_closing/finish_shutdown`，增加显式重试重新武装，并补齐快捷键身份和 HWND 延迟创建；窗口审查与分页审查均为 `PASS`。
