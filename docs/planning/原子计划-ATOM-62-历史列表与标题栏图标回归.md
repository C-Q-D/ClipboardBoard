# ATOM-62 历史列表占位与标题栏图标回归修复

## 问题契约

应用刚启动或复制新内容后，历史列表顶部出现约一张卡片高度的空白，最新卡片被
推到第二个位置，连续更新时卡片还会相互覆盖；同时托盘已有应用图标，但标题栏仍
可能显示默认图标。

## 根因与目标

1. `history-list`（兼容旧列表）和 `geometry-history-list`（当前显式几何列表）是同一
   `VerticalLayout` 的兄弟节点。Slint 的 `visible: false` 不会自动释放布局槽，隐藏的
   旧列表仍按 `vertical-stretch: 1` 占用高度，导致可见列表整体下移并出现重叠。
2. Slint/Winit 创建的真实 HWND 不会自动复用托盘加载的资源图标，必须在窗口显示后
   显式发送 `WM_SETICON`，并在 HWND 尚未稳定时允许后续定位重试。

目标是让两个列表模式严格互斥占位、保持最新记录从首行连续渲染，并让标题栏大小图标
   与托盘共用同一应用资源；不改变历史排序、复制、筛选或用户已确认的交互。

## 实现边界

- `ui/app-window.slint`：为两个互斥列表绑定条件伸展、最小/首选/最大高度，隐藏分支
  释放布局槽，显示分支独占可用高度。
- `src/platform/windows/window/lifecycle.rs`：从构建生成的资源常量加载应用图标，向
  真实面板 HWND 发送 `WM_SETICON`；找不到窗口或资源时安全返回，不阻断面板显示。
- `src/platform/windows/window/mod.rs`、`src/app/ui_event.rs`：导出并在窗口显示后及
  定位重试路径调用图标同步。
- 清理临时几何诊断代码；不得记录剪贴板正文或新增持久化字段。
