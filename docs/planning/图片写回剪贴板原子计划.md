## 总体计划

### 目标结果

用户点击图片历史卡片的“复制”按钮后，ClipboardBoard 在后台读取该记录绑定的耐久 PNG
原图，复核规范像素哈希，再把同一图片以 `CF_DIBV5` 写入 Windows 剪贴板。应用不模拟
粘贴按键，用户切换到目标程序后自行按 `Ctrl + V`。

### 验收场景

1. 图片卡片显示可点击“复制”，点击后面板保持可见。
2. 目标程序能够通过系统剪贴板取得复制的图片。
3. 图片原图缺失、损坏、路径或哈希不匹配时拒绝写回，不关闭面板、不修改历史列表或
   SQLite；允许现有交互把被点击卡片设为选中。
4. 图片写回产生的 `WM_CLIPBOARDUPDATE` 被一次性自身预期消费，不增加图片
   `copy_count`、不更新时间、不改变排序。
5. 旧面板代次、错误 ID/哈希、退出后的按钮事件继续被拒绝。
6. 文本复制行为、图片缩略图加载、图片删除回收和捕获格式优先级不回归。

### 明确排除

- 不自动执行 `Ctrl + V`，不恢复已经撤销的自动粘贴能力。
- 不写注册 `PNG`、`CF_BITMAP` 或多格式剪贴板事务；本轮只写 `CF_DIBV5`，由 Windows
  按需合成 `CF_DIB`/`CF_BITMAP`。
- 不增加大图预览、OCR、图片编辑、缩略图修复、目录设置或迁移。
- 不新增复制成功通知、失败弹窗或乐观历史更新；失败保持现有稳定诊断边界。

### 现状证据与调用关系

- `src/app/ui_event.rs` 已把按钮索引同步冻结为
  `(panel_generation, id, content_hash)`，并通过容量一复制槽投递。
- `src/history_bridge.rs` 的结果泵在后台按 ID 读取 `HistoryPayload`，当前只支持文本。
- `src/storage/worker.rs` 的 `HistorySummary` 已能返回经过领域校验的
  `HistoryImageSummary`，但 `HistoryPayload` 尚未携带图片资产。
- `src/image_decode` 已提供有界 PNG/DIB 解码；`CanonicalImagePixels` 已固定图片哈希
  协议。
- `src/clipboard/writer.rs` 已实现文本写回的串行 expectation、HGLOBAL 所有权和
  Close 失败语义。
- Microsoft Win32 契约：`CF_DIBV5` 是 `BITMAPV5HEADER` 后跟像素位图的全局内存；
  `SetClipboardData` 成功后系统取得 `GMEM_MOVEABLE` 内存所有权；Windows 可在
  `CF_DIBV5`、`CF_DIB` 和 `CF_BITMAP` 之间按需合成。

### 全局不变量

1. UI 事件和卡片 DTO 不携带原图字节、完整正文或可写文件 capability。
2. 文件读取、PNG 解码、DIBV5 编码、SQLite 查询和 Win32 写回都在现有结果泵后台线程
   执行。
3. 按 ID 读取后必须同时复核数据库哈希、文件规范像素哈希和 UI 请求哈希。
4. 原图路径只能由经过领域校验的 `ImageMetadata`、注册根和固定 `original` 子树组合；
   编码字节、尺寸和 RGBA 分配继续受现有固定上限约束。
5. `CF_DIBV5` 使用 124 字节 `BITMAPV5HEADER`、32 位 `BI_BITFIELDS`、明确 RGBA
   masks、负高度 top-down 和 BGRA 小端像素；不得包含文件头或 ICC profile。
6. 写回事务从 arm 到 sequence 绑定持有现有串行锁；`SetClipboardData` 成功后不得释放
   HGLOBAL。Close 失败仍绑定自身预期，再向调用方返回稳定错误。
7. 只有实际捕获为 `DibV5`、sequence 精确相同且解码后的规范哈希相同时，才能一次性
   消费图片自身预期；匹配必须发生在 ImageWorker 和 SQLite 之前。
8. 没有候选 expectation 的普通图片捕获不得为了抑制检查增加一次额外解码。
9. 日志只输出稳定错误类别，不记录图片字节、完整路径、窗口标题或剪贴板正文。
10. 每个原子独立验证、提交并推送 `origin/main`；连续执行，中间不等待人工确认。

## IMG-COPY-01 按 ID 返回图片复制载荷

- 状态：in_progress
- 支持的验收场景：场景 3、5。
- 唯一目标：存储线程按 ID 为图片记录返回经过领域校验的资产摘要。
- 当前行为与目标行为：当前 `HistoryPayload` 只返回文本字段；目标是在不读取文件的
  前提下，为 image 返回 `HistoryImageSummary`，为 text 返回 `image=None`。
- 前置条件与依赖：图片 v2 schema、`ImageMetadata` 和根注册表已完成。
- 代码定位依据：`src/storage/worker.rs` 的 `HISTORY_PAYLOAD_SQL`、
  `HistoryPayload`、`get_history_payload`；同文件的 `HistoryImageSummary` 和摘要行映射。
- 允许修改：存储 payload DTO、按 ID SQL/映射、存储定向测试、必要导出。
- 明确不修改：文件系统、图片解码、Win32、history bridge、UI。
- 实现步骤：
  1. 扩展 `HISTORY_PAYLOAD_SQL`，按图片根 ID LEFT JOIN 根注册表并读取完整图片字段。
  2. 为 `HistoryPayload` 增加 `image: Option<HistoryImageSummary>`。
  3. 使用 `ImageMetadata::new` 复核哈希、根、相对路径、尺寸和大小；根路径必须为绝对
     路径。
  4. text 必须没有图片字段；image 必须拥有完整图片字段和空文本正文；未知类型保持
     无图片载荷，供上层稳定拒绝。
- 接口、数据与错误契约：任一图片字段缺失、类型错误、哈希长度错误或根路径非法时整次

- 边界与异常：不存在仍返回 `Ok(None)`；坏数据不能 panic；文本既有字段原样保留。
- 测试要求：图片 payload 成功、文本 image 为空、不存在、缺字段、坏根、路径/哈希
  不匹配。
- 验证命令：`cargo test --locked storage::worker::tests --lib`
- 预期结果：调用方仅凭按 ID payload 就能取得只读图片资产身份。
- 完成判定：定向测试、Clippy lib 和 diff-check 通过，L2 DDD `PASS`。
- 交付给下一原子的输出：`HistoryPayload.image`。
- 停止或重新规划条件：必须改变 schema 或绕过领域路径校验。
- 风险等级：L2。
- DDD 门禁：编码前总体计划已通过；提交前隔离审查。

## IMG-COPY-02 校验原图并编码 DIBV5

- 状态：pending
- 支持的验收场景：场景 2、3。
- 唯一目标：把受限图片资产读取并转换成经过自校验的 `CF_DIBV5` 内存字节。
- 当前行为与目标行为：当前只为缩略图读取 WebP；目标是读取耐久 PNG 原图，复核规范
  身份并生成可交给 writer 的 DIBV5 bytes。
- 前置条件与依赖：IMG-COPY-01。
- 代码定位依据：`src/image_decode/png.rs`、`src/image_decode/dib.rs`、
  `src/domain/image_content.rs`、`HistoryImageSummary` 的路径组合。
- 允许修改：新增 `src/image_copy.rs`、模块导出、纯文件/编码测试。
- 明确不修改：Storage SQL、Win32 writer、history bridge、UI、原资产。
- 实现步骤：
  1. 构造固定 `canonical_root/original/relative-path`，要求绝对根和规范相对路径。
  2. 读取前检查普通文件与 30 MiB 编码上限，再有界读取完整 PNG。
  3. 调用现有 bounded PNG decoder，复核宽高和 canonical content hash。
  4. checked 分配 124 字节 V5 header 加 RGBA 长度；写入固定 masks、sRGB、top-down
     尺寸和 BGRA 像素。
  5. 返回不暴露路径且 Debug 不输出字节的拥有型 DIBV5 DTO。
- 接口、数据与错误契约：错误压缩为路径无效、文件不可用、文件超限、PNG 无效、身份
  不匹配、编码溢出；错误文本不得含路径。
- 边界与异常：透明 alpha 必须保持；横图、竖图、1×1 和最大允许尺寸均 checked；
  DIBV5 不含 `BITMAPFILEHEADER`。
- 测试要求：RGBA/BGRA roundtrip、alpha、top-down、多行、缺文件、目录冒充、超限、
  损坏 PNG、宽高/哈希不匹配；生成 bytes 经现有 `decode_dib` 后哈希完全相同。
- 验证命令：`cargo test --locked image_copy::tests --lib`
- 预期结果：得到可直接写入 `CF_DIBV5` 的可信 bytes。
- 完成判定：定向测试、Clippy lib 和 diff-check 通过，L3 DDD `PASS`。
- 交付给下一原子的输出：图片剪贴板写入 DTO。
- 停止或重新规划条件：现有 decoder 无法证明分配上限，或目标兼容性必须改为多格式。
- 风险等级：L3。
- DDD 门禁：强制提交前隔离审查。
- 计划提交信息：`feat(image): [IMG-COPY-02] 编码受限 DIBV5 载荷`

## IMG-COPY-03 写入 CF_DIBV5 并绑定预期

- 状态：pending
- 支持的验收场景：场景 2、4。
- 唯一目标：按现有所有权协议把 DIBV5 HGLOBAL 写入系统剪贴板。
- 当前行为与目标行为：writer 只支持 `CF_UNICODETEXT`；目标是新增
  `ClipboardWriteFormat::DibV5` 和图片写回入口。
- 前置条件与依赖：IMG-COPY-02。
- 代码定位依据：`src/clipboard/writer.rs` 的 expectation store、
  `write_unicode_text_raw`、`finish_transferred_write`。
- 允许修改：writer、clipboard 导出和 writer 定向测试。
- 明确不修改：捕获抑制消费、存储、history bridge、UI。
- 实现步骤：
  1. 增加 `DibV5` 格式身份及精确候选查询，不改变现有文本匹配。
  2. 对已验证 DIBV5 bytes checked 分配并复制到 `GMEM_MOVEABLE` HGLOBAL。
  3. 沿用串行锁执行 arm → Open → Empty → Set(CF_DIBV5=17) → sequence → Close →
     bind。
  4. Set 失败释放未转移内存；Set 成功后绝不释放；Close 失败仍绑定并返回
     `CloseFailed`。
- 接口、数据与错误契约：拒绝空或超过 DIB 上限的 bytes；candidate 只暴露布尔值，不
  暴露 pending 队列。
- 边界与异常：Expectation 队列满时在触碰剪贴板前拒绝；文本和图片连续写回按
  sequence/format/hash 独立消费。
- 测试要求：候选精确匹配、错误格式/sequence、一次性消费、连续文本/图片、
  Set/Close 所有权状态的可注入纯边界测试。
- 验证命令：`cargo test --locked clipboard::writer::tests --lib`；
  `cargo build --locked --bin clipboard-board`
- 预期结果：DIBV5 写回完成后有精确、有限、自身捕获可消费的 expectation。
- 完成判定：定向测试、Windows build、Clippy 和 diff-check 通过，L3 DDD `PASS`。
- 交付给下一原子的输出：DIBV5 writer 与 candidate/consume 协议。
- 停止或重新规划条件：Win32 API 需要延迟渲染或窗口所有者协议。
- 风险等级：L3。
- DDD 门禁：强制提交前隔离审查。

## IMG-COPY-04 抑制图片自身写回捕获

- 状态：pending
- 支持的验收场景：场景 4、6。
- 唯一目标：在任何图片发布或 SQLite 更新前一次性识别并跳过自身 DIBV5 写回事件。
- 当前行为与目标行为：捕获门禁只抑制文本；目标是仅在存在精确 DIBV5 candidate 时
  解码实际捕获并消费 expectation。
- 前置条件与依赖：IMG-COPY-03。
- 代码定位依据：`src/history_bridge.rs` 的 `run_clipboard_pump` 图片分支；
  `src/clipboard/io_worker.rs` 的文本抑制门禁；`ClipboardImageBytes` 格式枚举。
- 允许修改：history bridge 的写回抑制辅助逻辑、expectation 最小查询 API、定向测试。
- 明确不修改：ImageWorker、SQLite upsert、UI、普通捕获格式优先级。
- 实现步骤：
  1. 图片捕获到达 pump 后，先按 sequence 和实际 DibV5 格式查询 candidate。
  2. 无 candidate 直接走现有图片持久化，不增加额外解码。
  3. 有 candidate 时用现有 bounded DIB decoder 计算 canonical hash。
  4. 精确消费成功则跳过 ImageWorker/SQLite；不匹配则继续原捕获路径。
- 接口、数据与错误契约：只有 `ClipboardImageBytes::DibV5` 可匹配当前 writer；
  PNG/DIB 不得误吞。候选解码失败不消费预期。
- 边界与异常：错误 sequence、hash、format 均发布；预期仅消费一次；无图片上下文时
  自身事件仍应先抑制。
- 测试要求：匹配不发布且数据库不变、错误三元组继续发布、一次性消费、普通图片无
  candidate 不调用抑制 decoder。
- 验证命令：`cargo test --locked history_bridge::tests --lib`
- 预期结果：点击历史图片复制不会增加历史次数或改变排序。
- 完成判定：定向测试、Clippy 和 diff-check 通过，L3 DDD `PASS`。
- 交付给下一原子的输出：无回捕获副作用的图片写回闭环。
- 停止或重新规划条件：必须在 ClipboardIO 线程执行图片解码。
- 风险等级：L3。
- DDD 门禁：强制提交前隔离审查。
- 计划提交信息：`fix(history): [IMG-COPY-04] 抑制图片自身写回`
