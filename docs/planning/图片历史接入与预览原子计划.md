# 图片历史接入与预览原子计划

## 计划信息

- 计划 ID：`ATOMIC-IMAGE-HISTORY-UI-001`
- 父范围：`UNIT-10 / ATOM-36 / ATOM-37`
- 基线提交：`746788d`
- 执行模式：连续执行；每个原子独立定向验证、DDD 复核、提交并推送 `origin/main`。
- 用户验收点：全部原子完成后统一启动程序，验证图片捕获、历史恢复、图片卡片和删除清理。

## 大功能边界

本计划只完成以下闭环：

```text
Windows 图片剪贴板
  → ClipboardIO 复制一种拥有型 PNG/DIBV5/DIB 字节
  → ImageWorker 解码并耐久发布原图与缩略图
  → StorageExecutor 事务写入图片元数据
  → 历史查询/恢复返回图片摘要
  → UI 只为当前可见图片按需加载缩略图
```

明确不包含：

- 把历史图片重新写回系统剪贴板；该能力属于 `ATOM-38`。
- 图片 OCR、联网识别、预览大图、自定义图片目录设置界面。
- 全局界面重设计；图片卡片继承现有黑底白字、固定高度、明确操作区语法。

## 全局不变量

1. ClipboardIO 只在剪贴板打开期间复制一种拥有型 payload，跨类型优先级固定为
   `PNG > DIBV5 > DIB > Unicode 文本`；任何 `HGLOBAL`、`HBITMAP` 都不得跨线程。
2. 图片正式文件已经发布并回读验证后，才允许提交 SQLite。
3. SQLite 提交成功后才允许更新 UI；事务失败不得产生图片卡片。
4. 数据库失败时只回滚本次发布调用实际创建的资产，不删除此前已存在的同哈希资产。
5. 图片哈希冲突使用和文本一致的去重语义：保留原 ID、收藏、创建时间和资产身份，
   只更新最近复制时间、来源和饱和计数。
6. `ImageWorkerResult` 的 finalize 句柄必须恰好消费一次：数据库失败时 rollback；
   数据库成功且采用本次发布资产时 commit；数据库成功但复用旧资产时 rollback 本次
   资产。三个分支都必须等待 ACK，完成前不得开始下一张图片。
7. 历史查询 DTO 只携带图片元数据和可解析的缩略图定位信息，不携带原图字节。
8. 图片解码在线程外完成；Slint `Image` 只在 UI 事件线程创建和写入模型。
9. 未进入可见窗口的图片不得安排缩略图解码；快速滚动时旧代次结果必须作废。
10. 单条删除或清空事务提交后才回收无引用资产；回收失败不得回滚已经提交的历史事务，
    而是进入有界重试/后续对账边界。
11. ImageWorker 的捕获入口可以保持容量一 latest-wins；finalize、回收属于不可覆盖的
    控制命令，必须使用容量有界且带背压的 FIFO。退出顺序固定为：停止新剪贴板
    图片输入 → 排空图片持久化和 finalize → 拒绝新资产控制命令并排空 FIFO/回收重试
    到规定边界 → 关闭历史查询/变更 worker → 停止 ImageWorker → 关闭 StorageExecutor。
12. 诊断日志不得记录剪贴板正文、图片字节、完整本地资产路径或窗口标题。

## IMG-HIST-01 图片事务与根注册

- 风险：L3（持久化事务、幂等和文件/数据库一致性）。
- 唯一目标：StorageExecutor 可以在一个事务中注册当前图片根并 upsert 完整图片元数据。
- 允许修改：`src/storage`、图片领域 DTO、存储定向测试。
- 禁止修改：ClipboardIO、ImageWorker、UI、删除行为。
- 输入：
  - `ImageRootSnapshot` 的根 ID、根类型和规范路径。
  - `ImageMetadata`、来源程序和 `copied_at`。
- 输出：
  - `ImageUpsertResult`，包含 UI/历史所需的最终数据库快照、mutation revision 和
    `adopted_published_assets`。
- 实现契约：
  - 同一事务先 upsert 根注册，再 upsert 图片行，再读取最终快照。
  - 同根 ID 允许更新为当前规范路径，以支持已验证的资产根移动；同路径不同根 ID
    必须由唯一约束拒绝并回滚。
  - 图片行必须让文本正文为 `NULL`，预览只保存稳定元信息文案。
  - 重复哈希不得改变既有资产定位、收藏状态和创建时间。
  - 只有最终数据库快照采用本次提交的根和相对路径时，
    `adopted_published_assets=true`；重复记录保留旧资产身份时必须返回 `false`。
- 定向验证：
  - 新图片、重复图片、根冲突、SQL 故障回滚、重启恢复。
  - `cargo test --lib storage::worker::tests::<图片相关测试名>`
  - `cargo clippy --lib -- -D warnings`
- 计划提交：`feat(storage): [IMG-HIST-01] 提交图片历史事务`

## IMG-HIST-03 图片持久化协调器

- 风险：L3（跨 worker 顺序、finalize 恰好一次和退出排空）。
- 唯一目标：把图片捕获串接到 ImageWorker 和图片存储事务；DB/finalize 成功后仍对当前
  文本 UI 隐藏，图片 UI 投递延后至 IMG-UI-01。
- 允许修改：`src/history_bridge.rs`、`src/main.rs`、ImageWorker 接线、历史恢复/查询在

- 禁止修改：图片卡片渲染、图片写回剪贴板。
- 实现契约：
  - 文本捕获继续走现有路径；图片捕获提交 ImageWorker 后等待结果。

## IMG-HIST-04 图片删除与清空回收

- 风险：L3（删除提交和文件副作用的一致性）。
- 唯一目标：图片记录删除或清空提交后，异步回收已经无数据库引用的原图和缩略图。
- 允许修改：存储删除结果、历史变更桥、ImageWorker 资产命令和定向测试。
- 禁止修改：图片卡片、图片写回。
- 实现契约：
  - 删除事务返回待回收的受限资产引用；事务前不得删文件。
  - 删除同哈希不存在记录保持幂等。
  - 清空只回收事务实际删除且提交后已无引用的图片。
  - 回收路径必须由已注册根和领域相对路径重建并再次约束在固定子树内。
  - 回收失败不恢复数据库行；进入容量有界、次数有界且带退避的进程内重试队列。
    正常退出前排空到重试上限并记录放弃数量；更长期的磁盘对账仍由 `ATOM-49` 收敛。
  - 发布、回收和后续缩略图重建都由独占 `PreparedImageStorage` 的 ImageWorker 串行
    执行，禁止第二个组件自行拼接可写资产路径。
  - 回收进入不可覆盖的有界 FIFO；生产者按批次背压提交，清空图片数量超过队列容量时
    不得截断或覆盖，关闭时必须先排空 FIFO 和有限重试再 join。
- 定向验证：
  - 单条图片删除、文本删除不碰文件、清空混合类型、事务失败不回收、重复回收。
- 计划提交：`feat(history): [IMG-HIST-04] 回收无引用图片资产`

## IMG-UI-02 可见窗口缩略图卡片

- 风险：L3（异步图片解码、UI 线程所有权和滚动竞态）。
- 唯一目标：固定高度卡片只为可见图片加载缩略图，并在 UI 线程创建 Slint Image。
- 允许修改：缩略图加载器、`src/app/ui_event.rs`、`ui/app-window.slint`、UI 定向测试。
- 禁止修改：原图预览、图片写回、全局主题和面板尺寸。
- 实现契约：
  - Rust 根据 ListView 可见范围提交最多一屏加小缓冲的图片请求；面板打开、模型
    replace/append、删除/过滤、可见高度变化和 viewport 变化都必须进入同一个
    “可见性重算”入口，并按当前可见稳定身份集做请求差分。
  - 缩略图加载 worker 只读 WebP 并返回有界 RGBA8 像素 DTO；不得创建 Slint 对象。
  - 请求携带面板代次和卡片稳定身份；结果还必须属于最新可见身份集。滚出后又滚回的
    同一身份允许复用仍在途结果，滚出后未返回的结果会被拒绝并释放请求身份。
  - UI 事件线程使用像素 DTO 构造 `slint::Image`；缓存有明确条目数上限。
  - 图片卡片按已批准规范使用约 176px 固定内容高度，文本仍为 96px；窗口化列表用
    条目类型对应的已知固定高度维护可见范围，不按原图尺寸测量。缩略图使用固定预览区
    并保持比例裁剪；缺失、加载中和失败显示稳定占位。
  - 缩略图缺失或损坏时显示稳定“图片不可用”占位，不自动重建资产。自动修复需要新增
    数据库引用复核、原图重解码和资产发布协议，超出本轮可见卡片目标；按用户
    “不要过度设计”的约束留给后续可靠性切片。
  - 图片复制门禁沿用 `IMG-UI-01`，不得在本原子误启用。
- 定向验证：
  - 可见/不可见解码、快速滚动旧结果、坏 WebP、缺文件、横图/竖图/小图、混合固定
    高度选择和退出排空。
  - Windows Debug 构建和真实桌面启动；最终视觉/交互由用户统一验证。
- 计划提交：`feat(ui): [IMG-UI-02] 展示懒加载图片卡片`
