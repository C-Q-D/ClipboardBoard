## 总体计划

### 产品交付单元

本计划细化 `UNIT-10 / ATOM-30`，为后续图片捕获、编码、历史提交、展示、清理和
损坏恢复提供稳定的数据库与磁盘目录契约。

### 目标结果

- SQLite v1 文本库可事务升级到 v2，已有文本和历史 ID 不丢失。
- 每条图片记录绑定稳定的资产根 ID；切换目录时可以只让新图片使用新根，也可以在
  后续显式迁移旧资产。
- 图片路径只保存根内相对分片路径，原图与缩略图必须绑定同一内容哈希。
- 默认图片根为 `%LOCALAPPDATA%\ClipboardBoard\images`，同时预留专用自定义根。
- 自定义根不可用时返回明确回退结果，由后续设置 UI 提示用户。
- 目录认领可从中途失败恢复，并在 Windows 上拒绝重解析点与跨卷恢复目录。

### 验收场景

1. v1 库含短 BLOB 哈希的文本、已删除最高 ID 和完整来源字段时，升级后字段逐值
   保留，下一条 ID 不复用已经发放的高水位。
2. v2 重开只校验，不重复改表；坏 schema、孤儿根、错误 SQLite storage class、
   图片哈希与路径不一致均被拒绝。
3. 同一 32 字节内容哈希生成稳定的 `aa/<64hex>.png` 和
   `aa/<64hex>.webp` 相对路径。
4. 默认目录和合法自定义目录均建立受管目录；自定义目录失败时回退默认并保留失败
   分类。
5. claim 或 ready 临时文件发生空文件、截断和中途失败时，下一次准备可安全收敛；
   存在未知文件时不认领、不删除。
6. Windows 受管目录是重解析点或恢复根实际跨卷时拒绝准备；成功结果持有防止顶层
   目录被替换的句柄能力。

### 明确排除

- 不读取 PNG、DIB、DIBV5 或 `CF_BITMAP`。
- 不计算规范像素哈希，不编码 PNG/WebP，不写图片文件。
- 不提交或查询图片历史，不把资产根写入 SQLite 注册表。
- 不实现设置界面、设置文件、自定义目录选择器和目录迁移执行。
- 不展示图片卡片，不实现图片写回剪贴板。
- 不实现清理和损坏恢复；只固定其必须消费的安全目录能力。

### 已确认架构与代码接缝

- `src/storage/migration.rs` 使用 `PRAGMA user_version`、事务迁移和精确 schema 校验。
- `src/storage/worker.rs::initialize_connection` 是唯一 SQLite 连接初始化入口。
- `src/storage/migrations/001_initial.sql` 是 v1 文本表基线。
- `src/domain` 只保存拥有型数据和纯规则，不依赖 SQLite、UI 或 Win32。
- 新图片目录模块由库入口公开，但当前应用主流程不调用它。
- SQLite 是元数据真相源；PNG 原图是耐久 payload，WebP 缩略图是可重建缓存。

### 跨原子不变量

- v1 文本 `content_hash` 只保证 `BLOB NOT NULL`；32 字节限制只适用于图片。
- 图片行的数据库 `content_hash`、原图路径和缩略图路径必须表达同一哈希。
- `content_size` 固定表示已经发布的原图 PNG 文件字节数，范围为
  `1..=i64::MAX`；后续空间配额必须统计原图和缩略图的实际文件大小。
- 图片数据库路径只保存各固定子树内的两组件相对路径，不保存绝对路径。
- 一个图片根使用稳定 `root_id`；移动目录不改变该 ID，准备结果另行返回当前规范路径。
- 后续 `ATOM-36` 必须按 `root_id` 在同一事务 upsert 当前根路径；不同根 ID 占用同一
  路径时拒绝。
- 后续 `ATOM-35/49/55` 必须借用安全目录 capability；清理和恢复不得接受裸
  `PathBuf` 递归操作，并须逐项拒绝重解析点。
- 代码和测试新增文件必须有中文文件、类型、字段、方法和关键逻辑注释。

### 原子依赖顺序

1. `PERSIST-01`：SQLite v2 图片元数据迁移。
2. `PERSIST-02`：图片领域元数据。
3. `PERSIST-03`：图片相对路径和目录布局。
4. `PERSIST-04`：安全目录准备与自定义路径回退。

### 整体验证

- 只运行迁移、受影响存储夹具、图片领域和目录模块的针对性测试。
- 运行库目标 `cargo check`、库 Clippy、中文注释门禁和 Windows 目标检查。
- 不运行全量测试套件。

### 执行与 Git 策略

- 执行模式：连续执行；四个原子全部完成后暂停并启动程序供用户验证。
- 每个原子独立验证、L2/L3 DDD 复核、提交并推送 `origin/main`。
- 规划文档先独立提交并推送；原子状态与对应实现放在同一提交。

## PERSIST-01 建立 SQLite v2 图片元数据迁移

- 状态：in_progress
- 支持的验收场景：场景 1、2。
- 唯一目标：SQLite 在单个事务中兼容升级并严格表达图片记录与资产根引用。
- 当前行为与目标行为：当前最高版本为 v1，只包含文本列；完成后最高版本为 v2，
  v0、v1 和 v2 均经过唯一迁移入口到达并校验同一结构。
- 前置条件与依赖：ATOM-29 已完成；唯一 SQLite 连接和 v1 精确校验已经存在。
- 代码定位依据：`src/storage/migration.rs::migrate`、
  `validate_v1_schema`、`src/storage/worker.rs::initialize_connection` 和
  `src/storage/migrations/001_initial.sql`。
- 允许修改：存储迁移模块、迁移 SQL、唯一连接初始化、被 v2 约束影响的存储测试夹具、
  存储错误文案、注释门禁清单和本计划状态。
- 明确不修改：领域图片 DTO、目录模块、图片 CRUD、UI、剪贴板读取和设置。
- 实现步骤：
  1. 在连接开启任何事务前设置并读回 `PRAGMA foreign_keys=ON`。
  2. 新增 v2 SQL，以新表复制、删除、重命名的事务方式重建 `clipboard_items`，并创建
     `image_asset_roots`。
  3. 迁移前读取 `sqlite_sequence` 高水位，复制显式 ID 后恢复
     `max(旧高水位, max(id))`。
  4. 图片字段使用 all-or-none CHECK；非图片行所有图片字段为空。
  5. 图片哈希限定 BLOB 32 字节，路径固定为小写哈希分片并与
     `lower(hex(content_hash))` 一致；文本继续兼容 v1 短 BLOB。
  6. 精确校验两张表、索引、外键和 CHECK 结构，并执行 `foreign_key_check`。
  7. 更新只需要“非文本”语义的旧夹具；确需图片语义的夹具插入合法根和完整图片行。
- 接口、数据与错误契约：
  - `image_asset_roots.root_id` 为 32 字节 BLOB 主键；`root_path` 是非空 TEXT 且唯一；
    `root_kind` 仅为 `default/custom`；`created_at` 是 INTEGER。
  - 图片新增字段为 `image_root_id`、`image_path`、`thumbnail_path`、
    `image_width`、`image_height`、`image_format`、`content_size`。
  - 宽高为 `1..=u32::MAX` 的 SQLite INTEGER；`content_size` 为
    `1..=i64::MAX`；`image_format='png'`。
  - v1 已有伪图片行不是已发布产品数据，迁移应以不兼容错误整体回滚。
- 边界与异常：未来版本拒绝；错误 storage class、孤儿根、错配哈希、坏索引、坏外键
  和迁移中途 SQL 错误均不得留下 v2 半状态。
- 测试要求：覆盖 0→2、1→2、2 重开、未来版本、一字节文本哈希逐值保留、已删除
  最高 ID 后下一 ID 为 101、孤儿根、REAL 尺寸、TEXT 根 ID、错配路径哈希、
  伪图片行拒绝和事务回滚；运行所有受影响存储夹具。
- 验证命令：迁移模块测试；受影响的 `storage::worker` 定向测试；
  `cargo check --lib`；库 Clippy；中文注释门禁。
- 预期结果：schema 版本为 2，文本和高水位保留，非法图片状态无法提交。
- 完成判定：迁移测试及受影响存储测试通过，完整 diff 经 L3 DDD 返回 PASS。
- 交付给下一原子的输出：稳定的 v2 列、根表和 SQLite 错误语义。
- 停止或重新规划条件：无法在事务内保留 v1 文本或自增高水位；开启外键破坏现有
  合法生产数据。
- 风险等级：L3
- DDD 门禁：提交前强制复核迁移、回滚、兼容性和外键。
- 计划提交信息：`feat(storage): [PERSIST-01] 建立 SQLite v2 图片元数据迁移`

## PERSIST-03 建立图片路径布局

- 状态：pending
- 支持的验收场景：场景 3。
- 唯一目标：从内容哈希和资产根稳定生成固定子树内的图片路径。
- 当前行为与目标行为：当前只有数据库数据目录；完成后路径布局能表达默认根、自定义
  根、原图、缩略图、staging 和外部同卷恢复基目录。
- 前置条件与依赖：PERSIST-02 已提交。
- 代码定位依据：`src/storage/mod.rs::default_data_directory`、架构图片资产树和领域路径类型。
- 允许修改：新图片存储模块、库入口、路径纯函数测试、注释门禁、架构路径说明和计划状态。
- 明确不修改：文件系统创建、marker、Win32 句柄、SQLite、设置和图片编码。
- 实现步骤：
  1. 建立默认和自定义根偏好 DTO。
  2. 以小写 64 位十六进制生成原图和缩略图两组件相对路径。
  3. 将相对路径分别解析到 `original` 和 `thumbnail` 固定子树。
  4. 默认恢复基目录位于应用根 `recovery`；自定义恢复基目录位于自定义根父目录的
     `.clipboardboard-recovery`，均不在资产根内部。
- 接口、数据与错误契约：自定义路径必须是绝对专用子目录，不得是文件系统根、盘符根
  或 UNC share 根；布局只构造路径，不证明目录安全。
- 边界与异常：缺少 `LOCALAPPDATA` 返回明确错误；路径解析不得让相对路径替换根。
- 测试要求：固定哈希快照、默认路径、自定义路径、恢复目录在根外、错误根路径和两类
  文件扩展名。
- 验证命令：图片路径布局模块测试；`cargo check --lib`；库 Clippy；中文注释门禁。
- 预期结果：路径输出确定、可比较且不访问文件系统。
- 完成判定：纯路径测试通过，完整 diff 经 L2 DDD 返回 PASS。
- 交付给下一原子的输出：目录准备所需的资产根和恢复基目录布局。
- 停止或重新规划条件：自定义根父目录无法形成外部恢复基目录。
- 风险等级：L2
- DDD 门禁：提交前复核路径边界和未来多根接缝。
- 计划提交信息：`feat(image): [PERSIST-03] 建立图片资产路径布局`

## PERSIST-04 安全准备图片目录并支持回退

- 状态：pending
- 支持的验收场景：场景 4、5、6。
- 唯一目标：安全、幂等地认领并准备默认或自定义图片目录。
- 当前行为与目标行为：当前没有图片目录生命周期；完成后调用方得到已准备目录、稳定
  根 ID、当前规范路径、来源/回退原因及 Windows 安全句柄 capability。
- 前置条件与依赖：PERSIST-03 已提交。
- 代码定位依据：PERSIST-03 布局、新图片存储模块和 Windows 平台依赖配置。
- 允许修改：图片目录准备模块、Windows 目录守卫、Cargo Windows features、模块测试、
  注释门禁、架构和后续原子安全契约、本计划和项目状态。
- 明确不修改：图片文件写入、SQLite 根注册、设置持久化、目录迁移执行、清理和恢复执行。
- 实现步骤：
  1. 资产根与恢复基目录分别使用不可变 claim 和独立 ready 标记。
  2. claim/ready 均通过固定临时名、写入、flush、关闭和同目录 rename 发布。
  3. 严格协议状态允许重写唯一空白/截断临时文件；任何额外未知条目拒绝且不删除。
  4. 有效 claim 缺 ready 表示 preparing，可幂等续建；ready 后仍复核所有受管目录。
  5. 新根 ID 使用首次规范路径的域分隔 BLAKE3；marker 保存创建指纹，移动后沿用根 ID，
     capability 另返回当前规范路径。
  6. 自定义任一步失败时准备默认根，并返回包含请求路径和分类原因的 fallback。
  7. Windows 用不共享 DELETE 的目录句柄验证非重解析点、最终路径边界和相同卷序列；
     capability 存活期间禁止顶层目录替换。
- 接口、数据与错误契约：
  - marker 是防误操作协议，不是防伪安全凭据。
  - `PreparedImageStorage` 不可克隆；Windows 内部持有资产根、三个固定子目录和恢复基
    目录句柄。
  - fallback 结果不吞掉原因；默认目录失败直接返回错误。
  - 后续 `ATOM-36` 按根 ID upsert 当前规范路径；同路径不同根 ID 冲突必须拒绝。
- 边界与异常：磁盘满、权限失败、临时文件截断、进程在任一步退出、已有未知文件、
  marker 版本错误、顶层 reparse、最终路径越界和恢复目录跨卷。
- 测试要求：空/截断/完整临时文件恢复；每个步骤一次失败后重试；未知文件不动；
  自定义失败回退；A→B 移动根 ID 不变而当前路径更新；Windows 普通目录句柄、reparse
  拒绝和卷序列检查。
- 验证命令：目录准备模块定向测试；Windows 目录守卫测试；`cargo check --lib`；
  Windows 目标检查；库 Clippy；中文注释门禁。
- 预期结果：准备成功返回安全 capability；失败不会认领未知目录，自定义失败可回退。
- 完成判定：定向测试通过，完整 diff 经 L3 DDD 返回 PASS。
- 交付给下一原子的输出：ATOM-31/35 可消费的稳定路径与安全目录能力；ATOM-30 完成。
- 停止或重新规划条件：Windows 无法在现有权限下取得目录 identity/卷信息；marker
  状态无法在不删除未知文件的前提下收敛。
- 风险等级：L3
- DDD 门禁：提交前强制复核故障恢复、目录认领、重解析点和回退语义。
- 计划提交信息：`feat(image): [PERSIST-04] 安全准备图片存储目录`
