## 目标与执行模式

本计划把 ATOM-40～ATOM-60 从单工作区串行执行改为受控的本地 worktree 并行执行，
并记录本轮用户裁剪后的执行范围：取消 ATOM-48 图片空间配额，完整 ATOM-50/51、
ATOM-49、ATOM-54、ATOM-55 暂缓，仅保留图片路径配置、快捷键、开机启动和 ATOM-56。
并行只缩短相互独立模块的等待时间，不取消原子边界、针对性验证、双 DDD 门禁、
独立提交、主线集成验证或最终真实 Windows 验收。

- 模式：连续执行，全部任务完成前不要求用户逐项确认。
- 实现并发：主 Agent 加最多两个实现 Worker。
- 评审并发：始终保留一个 Agent 槽给隔离 DDD。
- 远端：Worker 的 `codex/*` 分支不得设置 upstream、不得 push、不得创建远端分支。
- 主线：只有完成最终集成验证的原子提交可以快进到 `main`，随后只推送
  `origin/main`。
- 最终交付：Release 程序、测试与验收记录、发布与运维文档、逐项人工验证清单。

## Worktree 与分支契约

### 路径

所有 worktree 位于：

`F:\workspace\small-projects\windows-copy-worktrees\`

每个正式 Worker 使用新的绝对路径和新的本地 `codex/*` 分支。不得在主仓库内嵌套
worktree，不得复用已经基于旧主线开发过的分支。

### 基线证明

每张原子计划必须记录：

- `base_main_sha`；
- 依赖原子的主线提交 SHA；
- `git merge-base --is-ancestor <dependency> <base_main_sha>` 的结果；
- 分支名和 worktree 绝对路径。

依赖不在基线祖先中时禁止编码。不得通过 merge 前置分支来升级旧 worktree。

### 文件所有权

Worker 只能修改分配的代码、测试和当前原子的唯一中文计划文档。以下共享状态只由
主 Agent 在集成 worktree 修改：

- `AGENTS.md`；
- `原子开发任务计划.md`；
- `docs/planning/开发计划.md`；
- `docs/ai-project/项目工作台.md`；
- `docs/ai-project/项目阶段记录.md`。

一原子一份计划文档，路径为
`docs/planning/原子计划-ATOM-<编号>-<中文简称>.md`。不得在当前原子提交中提前声明
后续原子完成。

## 双 DDD 门禁

L2/L3 原子必须通过两个不同的隔离评审任务：

1. 编码前计划门禁：审查原子卡、契约和相关接口。
2. 提交前最终差异门禁：审查完整 diff、调用方和测试证据。

两个实现 Worker 同时到达门禁时进入单一 DDD 队列。评审必须使用新的
`fork_turns=none` 只读 Agent。原子计划记录两个评审任务名、结果，以及提交前待审
diff 的内容哈希。最终集成 diff 发生任何实质变化时重新执行提交前 DDD。

## 原子提交与主线集成事务

### Worker 分支

Worker 在本地完成代码、测试、当前原子计划和必要 DDD 后创建一个本地原子提交。
该提交只表示“分支完成”，不表示已经进入主线或推送远端。

### 集成 worktree

主 Agent 为每个待集成原子从当前已验证 `main` 创建新的可丢弃本地
`codex/integration-*` worktree：

1. 记录 `pre_integration_sha`。
2. 使用 `git cherry-pick --no-commit <worker_commit>` 应用单个 Worker 提交。
3. 无冲突后加入共享状态文档回写。
4. 对最终完整 diff 运行针对性验证和必要的提交前 DDD。
5. 只创建一个最终主线原子提交。
6. 在主仓库执行 `git merge --ff-only <integration_branch>`。
7. 核对主线构建和工作树后只推送 `origin/main`。

发生 cherry-pick 冲突时立即 abort，不在集成 worktree 手工修正。Worker 必须从最新
`main` 新建分支，生成替代提交，重新验证并重新通过双 DDD。

非冲突验证失败时先分类：

- 环境瞬态：修复隔离环境后重新验证，不改代码。
- Worker 代码缺陷：退回原 Worker，从最新 `main` 生成替代提交，重新测试和提交前
  DDD。
- 集成接线缺陷：由主 Agent 建立独立接线原子，重新计算 diff 哈希并执行双 DDD。

失败的集成 worktree 和本地分支可以丢弃并从 `pre_integration_sha` 重建；`main`
始终停留在上一个已验证提交，验证前不得 push。

## Windows 全局状态隔离

Worker 只允许运行使用唯一临时根的单元或模块集成测试：

- 每个 worktree 使用独立 `target`；
- 数据库、图片和配置测试使用 worktree 唯一临时目录；
- 禁止 Worker 启动真实应用；
- 禁止访问默认 `%LOCALAPPDATA%\ClipboardBoard`；
- 禁止操作真实系统剪贴板、托盘、单实例互斥体、HKCU Run、安装器或卸载器。

真实 Windows 测试由主 Agent 独占执行。每个测试必须：

1. 把当前系统状态写入持久化恢复清单；
2. 创建进行中 marker；
3. 使用 `try/finally` 或等价机制恢复；
4. 下次测试前先处理遗留 marker；
5. 恢复失败时冻结后续全局测试并保留证据。

性能测试期间暂停其他 Worker 的构建、测试和真实程序运行，避免污染预算。

## Worktree 清理

本地 worktree 和分支保留到全部任务、最终验收资料和主线推送完成。之后只允许在上述
专用 worktree 根内按已解析绝对路径清理；主仓库、用户目录和其他路径不得作为递归
删除目标。
