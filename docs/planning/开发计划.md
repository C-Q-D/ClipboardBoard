# ClipboardBoard 开发计划

## 执行方式

- 模式：连续原子执行。
- 原子顺序：严格使用根目录《原子开发任务计划》；当前先执行 ATOM-25R 的 `WCB-INT-01` 至 `WCB-INT-10`，全部完成后再进入 ATOM-26，随后继续至 ATOM-60。
- 同一时间：只允许一个原子处于进行中状态。
- Git：每个原子验证通过后创建独立提交并推送 `origin/main`；用户已明确授权后续远端同步。
- 风险：L2/L3 原子编码前和提交前均执行隔离质疑。

## 里程碑

| 里程碑 | 原子范围 | 完成结果 |
|---|---|---|
| M0 技术骨架 | 01–07 | 热键、面板、托盘、日志和线程边界可用 |
| M1 文本实现基线 | 08–22 | 文本捕获、持久化和历史复制实现完成；自动粘贴由后续产品决策撤销 |
| M2 文本完整 MVP | 23–29，含 25R | 持续置顶、鼠标显式复制、SQLite 分页、搜索、筛选和历史管理可用 |
| M3 图片完整 MVP | 30–43 | 图片复制、图片兼容分页、懒加载和性能门禁可用 |
| M4 隐私与稳定性 | 44–55 | 设置、隐私、清理和恢复可用 |
| M5 正式发布 | 56–60 | 图标、性能、安装、验收资料完成 |

## 验证策略

- 原子内：优先运行直接单元、集成或 Windows 场景测试。
- 交付单元：运行受影响模块的回归测试和实际用户路径。
- 发布：Release 性能门禁、安装冒烟、Windows 10/11、DPI、多屏和管理员目标矩阵。

## 恢复入口

每次接管时：

1. 检查 Git 状态和当前分支。
2. 阅读《原子开发任务计划》的“当前原子”和最后执行记录。
3. 阅读本文档、项目工作台和当前原子涉及的代码。
4. 只执行第一个未完成且依赖已满足的原子。
