## 一、交付结果

用户可以在任意文本历史卡片上点击收藏按钮，并获得以下可观察行为：

- 未收藏记录可以收藏，已收藏记录可以取消收藏。
- 按钮只在 SQLite 事务提交成功后改变最终收藏状态，不做可能误导用户的乐观更新。
- 收藏状态重启后仍存在；再次复制相同内容时保留原收藏状态。
- “收藏”标签只显示已收藏记录；在该标签内取消收藏后，记录会从当前结果中移除。
- 收藏失败时卡片保持原状态，并显示固定重试提示，不展示正文、SQL 或原生错误。
- 同一时刻只接受一个收藏变更，避免双击或迟到结果造成状态反转。

## 二、范围边界

### 本计划包含

1. SQLite 收藏期望状态事务和稳定身份校验。
2. 有界异步收藏命令桥、工作线程和退出排空顺序。
3. 卡片收藏按钮、处理中状态、结果隔离和收藏筛选刷新。

### 本计划不包含

- 删除单条记录、清空历史或批量收藏。
- 图片收藏、图片捕获或图片筛选。
- 收藏排序、收藏分组、标签和云同步。
- 键盘收藏快捷键。
- 自动粘贴、`Ctrl + Enter` 或其他已删除的键盘复制入口。

## 三、全局契约

### 数据一致性

1. 收藏命令传递明确的期望状态 `is_pinned`，禁止使用数据库盲切换，确保重试具有幂等性。
2. 变更必须同时校验数据库 `id` 和严格 32 字节 `content_hash`；身份不匹配时不得修改其他记录。
3. SQLite worker 是唯一数据库连接所有者；收藏提交继续通过 `StorageClient` 串行进入该 worker。
4. 事务必须在返回成功前完成提交；影响行数不是一条时返回有限失败结果。
5. 现有重复文本 upsert 不覆盖 `is_pinned`，并通过针对性测试固定该不变量。

### 并发与生命周期

1. Slint 回调不访问 SQLite，只同步解析当前卡片的稳定身份并尝试投递有界请求。
2. 同一时刻最多存在一个收藏请求；请求处理中拒绝新的收藏点击。
3. UI 只接受与当前 pending 身份、期望状态和请求令牌完全一致的结果。
4. 收藏结果不能被旧历史查询覆盖；成功后使旧数据集和分页请求失效，并从 SQLite 重新查询当前筛选。
5. 退出时先关闭收藏请求入口并等待在途事务完成，再建立 storage 的关闭线性化点。

### 隐私与错误

1. 收藏请求、结果、诊断日志和 UI 状态不得携带完整剪贴板正文。
2. 用户界面只显示固定失败提示“收藏更新失败，请重试”。
3. 队列满、应用关闭、身份失效和存储失败均不得提前改变收藏状态。

### 验证与提交

1. 每个原子只运行覆盖本次变更的针对性测试、必要 Windows 构建和差异检查，不运行全量测试。
2. 三个原子分别验证、DDD 复核、提交并推送至已授权的 `origin/main`。
3. 整个收藏功能完成后启动程序，暂停等待用户实际验证。

## 五、原子任务

### [x] FAV-01 增加收藏状态事务

- 唯一目标：存储层可以按稳定身份把一条历史记录设置为明确的收藏状态。
- 风险等级：L2。
- 允许修改：`src/storage`、存储定向测试和本计划执行记录。
- 明确不修改：UI、Slint、历史查询线程和主程序生命周期。
- 实现契约：
  1. 增加拥有型 `SetPinnedInput` 和有限结果类型，只包含 ID、哈希与期望状态。
  2. `StorageExecutor` 与 `StorageClient` 暴露同语义接口。
  3. worker 在事务内执行 `UPDATE ... WHERE id = ? AND content_hash = ?`，只接受影响一行。
  4. 成功提交后返回数据库最终收藏状态；失败或身份错配不产生修改。
  5. 重复设置同一期望状态成功且没有反转语义。
- 针对性测试：重启持久化；幂等重试；身份错误无修改；重复 upsert 保留收藏。
- 计划提交：`feat(storage): [FAV-01] 增加收藏状态事务写入`

#### 执行记录

- 实际结果：增加 `SetPinnedInput/SetPinnedResult`、双身份事务写入和
  `StorageExecutor/StorageClient` 公共接缝；收藏与取消收藏均在提交后返回。
- 针对性验证：收藏、取消收藏重启持久化，幂等重试，错误 ID/哈希零修改，
  重复 upsert 保留收藏共 2 项测试通过；Windows MSVC check 和差异检查通过。
- DDD 结果：`PASS`，确认期望状态、事务回滚、身份校验和隐私边界成立。

### [x] FAV-02 接入异步收藏命令桥

- 唯一目标：UI 可以通过有界非阻塞入口把收藏请求交给后台，并在退出前排空已接受事务。
- 依赖：`FAV-01`。
- 风险等级：L3。
- 允许修改：新增收藏命令桥模块、模块导出、`src/main.rs` 和桥接定向测试。
- 明确不修改：Slint 视觉、卡片按钮和筛选 reducer。
- 实现契约：
  1. 有界请求队列容量为一，`try_submit` 不阻塞 UI。
  2. 请求包含单调令牌、ID、哈希和明确期望状态，不包含正文。
  3. 单工作线程顺序调用 `StorageClient`，把有限成功或失败结果投递回 UI 事件入口。
  4. 关闭后拒绝新请求；关闭前已接受的请求必须完成数据库事务。
  5. 主线程先关闭并 join 收藏 worker，再调用 `storage.begin_closing()`。
- 针对性测试：队列边界；有限结果；关闭排空；Windows 目标编译。
- 计划提交：`feat(history): [FAV-02] 接入异步收藏命令桥`

#### 执行记录

- 实际结果：增加容量为一的非阻塞收藏请求桥、单 worker、完整 mutation 身份回显、
  有限错误映射和主程序先排空收藏再关闭 SQLite 的生命周期接线。
- 针对性验证：满队列/关闭拒绝、关闭排空并重启持久化、陈旧身份有限失败共 3 项
  测试通过；Windows MSVC check 和差异检查通过。
- DDD 结果：`PASS`，确认关闭线性化、UI 结果投递失败不影响落盘和反向清理顺序成立。

### [x] FAV-03 完成收藏按钮与筛选闭环

- 唯一目标：用户通过卡片按钮完成收藏或取消收藏，并在当前筛选中看到提交后的真实结果。
- 依赖：`FAV-02`。
- 风险等级：L2。
- 允许修改：`ui/app-window.slint`、`src/app/ui_event.rs`、必要的内存历史辅助方法和 UI 定向测试。
- 明确不修改：删除、图片、设置和键盘复制入口。
- 实现契约：
  1. 卡片 DTO 增加 `is_pinned` 与 `pin_pending`，按钮显示空心/实心星形和处理中状态。
  2. 点击时同步解析当前索引对应的 ID 与哈希，生成相反的明确期望状态。
  3. 请求被接受后只显示处理中，不改变 `is_pinned`；提交成功结果匹配后才更新。
  4. 失败、身份不匹配、队列满或迟到结果保持原状态，并显示固定失败提示。
  5. 成功后作废旧查询数据集并重新查询当前关键词和筛选；在“收藏”标签取消收藏后记录消失。
  6. pending 期间禁用新的收藏点击；隐藏面板不取消已经接受的持久化事务。
- 针对性测试：稳定身份；提交后更新；双击与迟到隔离；收藏筛选刷新；Slint 编译；Windows 最小桌面冒烟。

- 竞态收口：全局单 pending；五元 mutation 身份；隐藏/重开不取消在途事务；
  入队失败恢复按钮；成功先推进数据集，旧首页和续页不能覆盖新状态。
- 针对性验证：收藏 reducer 7 项、内存身份同步 1 项、收藏按钮命中区 1 项、
  复制和选择命中区回归各 1 项通过；Clippy、中文注释、Windows MSVC check
  和差异检查通过。
