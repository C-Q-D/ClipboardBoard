## 一、交付结果

用户通过带有可见文字的“清空全部”危险入口进入强确认区。确认区必须明确显示
“将删除全部记录，包括已收藏记录”；只有精确输入“清空全部”后才能提交。取消不产生
存储请求；事务失败时 UI 不变化；事务成功后删除 SQLite 中全部类型和收藏状态的记录，
同时拒绝旧捕获、旧首页和旧续页复活。清空事务之后提交的新捕获仍应保留。

## 二、验收场景

| 场景 | 可观察结果 |
|---|---|
| `SC-FULL-01` 强确认门禁 | 危险入口有“清空全部”文字；未输入或输入错误短语时不能确认。 |
| `SC-FULL-02` 取消 | 关闭确认区，不提交后台请求，数据库与 UI 均不变化。 |
| `SC-FULL-03` 确认 | 精确输入后提交；成功删除未收藏、收藏和非 text 行。 |
| `SC-FULL-04` 路由隔离 | 原“清理未收藏”只能显式发送 `UnpinnedText`，收藏和非 text 行保持。 |
| `SC-FULL-05` 失败 | 队列拒绝、SQL 或提交失败时保留全部记录并显示固定提示。 |
| `SC-FULL-06` 幂等 | 空库再次清空仍成功并推进单调存储修订号。 |
| `SC-FULL-07` 并发捕获 | 事务前捕获被清除；事务后成功提交的新捕获被保留。 |
| `SC-FULL-08` 迟到状态 | 旧捕获、旧首页、旧续页、旧选择和旧游标不能复活已删除记录。 |
| `SC-FULL-09` 隐藏与退出 | 已接受事务在面板隐藏或退出期间仍完成，storage 最后关闭。 |

## 三、明确排除

- 不删除尚未存在的图片磁盘资产，不提前实现 ATOM-30 的图片 schema 或目录。
- 不实现撤销、回收站、自动清理、键盘清空快捷键或操作系统弹窗。
- 不改变单条删除、收藏、复制、搜索、分页和“清理未收藏”的既有产品语义。
- 不运行全量测试，只运行当前原子和受影响交互的定向测试。

## 四、跨原子不变量

### 存储与顺序

1. 唯一 storage worker 是 upsert、清空未收藏和清空全部的线性化点。
2. 三类操作共享 `storage_mutation_revision`；SQL 前使用 `checked_add` 预留，事务提交
   成功后才安装。耗尽、SQL 或提交失败不得推进水位。
3. 清空全部必须在单个事务中执行无筛选的 `DELETE FROM clipboard_items`。
4. 删除零行是幂等成功，也获得新的修订号；不得提前操作未来图片资产目录。

### 路由与桥

1. `ClearHistoryScope` 只允许 `UnpinnedText` 和 `All`，不得实现 `Default`，不得提供
   无参或隐式选择危险范围的构造。
2. 请求必须显式携带 scope；结果必须原样回显 scope、mutation token 和 panel generation。
3. 原“清理未收藏”入口只能构造 `UnpinnedText`；只有通过文字强确认的新入口才能构造 `All`。
4. 两种范围共享一个容量一的 clear-history worker，不增加第二条常驻线程。
5. 关闭不丢弃已接受请求；clear worker 必须在 storage 关闭前排空并 join。

### UI 一致性

1. pin、delete、`UnpinnedText` 和 `All` 共享 UI 全局 mutation 互斥。
2. 事务成功前不得乐观删除；失败或提交拒绝时保留全部卡片。
3. 两种清空成功均推进同一个只增不减的 `active_clear_revision`。
4. `All` 成功时统一过滤 snapshot、MemoryHistory 和 capture revision 索引：仅保留
   `capture_revision >= clear_revision` 的事务后捕获；重算选中项。
5. 成功后取消搜索，推进 history dataset generation，清除旧 pending request/cursor，
   并按当前 text 筛选刷新；旧查询不能写回。
6. 当前产品不存在独立详情、预览或计数面板；若实现中发现新的记录派生状态，必须纳入
   committed-clear reducer，不能让其引用已删除记录。
7. 隐藏面板关闭确认区和输入文本，但不能取消已经进入后台的清空事务或降低水位。

## FULL-02 双范围清空命令桥

  `src/history.rs` 和直接 UI/集成测试。
