# ClipboardBoard 界面重设计原子开发计划

## 0. 给执行模型的强制说明

本文不是建议清单，而是完整交付目标。后续模型收到“以本文为目标执行”后，必须先完整阅读本文，再从原子 UIR-01 开始按依赖顺序连续执行到 UIR-18。除本文明确列出的停止条件外，不得临时改变交互、跳过原子、合并多个原子提交或用“后续再完善”替代验收。

每个原子固定执行以下闭环：

1. 确认前置原子已经在当前分支完成，并核对工作区没有混入用户文件。
2. 只修改该原子“允许修改”中的文件；发现必须越界时先按停止条件重规划。
3. 先补充或更新该原子的定向测试，再完成最小实现。
4. 只运行该原子列出的定向命令；禁止为了省事运行全量测试，也禁止 cargo clean。
5. 对标为 L2 的原子，在提交前使用隔离上下文执行 DDD 复核；DDD 不能替代定向测试。
6. 将本文执行台账中的状态、测试结果、DDD 结论和提交号一并回写。
7. 每个原子独立本地提交。只有执行会话仍包含用户明确的远端同步授权时才推送；本文本身不扩大 Git 远端权限。
8. 当前原子未通过时不得进入下一个原子，也不得提交“半完成”状态。

编译必须复用同一个 target 目录和 Cargo 增量缓存。不要为每个原子创建新的 CARGO_TARGET_DIR，不要删除 target，不要重复执行 Release 全量构建。Slint 根文件变化会重新运行界面代码生成，但已经编译的 Rust 依赖不会正常情况下从头编译。

## 2. 唯一产品目标

把当前单列、操作按钮分散在每条记录上的黑色面板，改造成一个中性深色、连续外框、左右双栏的剪贴板工作台：

- 左侧负责搜索结果、类型筛选和紧凑历史列表。
- 右侧负责当前选中内容的文本或图片预览，以及收藏、删除、复制操作。
- 最近复制的内容始终位于真实列表第一项，不允许出现占位空行、卡片覆盖或层级错位。
- 文本和图片是仅有的两种内容类型；不增加代码识别、富文本渲染、OCR 或联网解析。
- 复制仍由用户点击明确的“复制文本”或“复制图片”按钮触发；程序只写回系统剪贴板，用户自己按 Ctrl+V。
- 鼠标点击历史项是唯一改变选择的直接交互；上下键不再改变选择，Enter 不复制也不粘贴，Esc 隐藏到系统托盘。
- Alt+V 保留切换面板行为；面板显示后保持置顶，点击其他软件不自动隐藏。
- 搜索、防抖、筛选、收藏、删除、清空、无限滚动、游标分页、缩略图缓存和迟到事件隔离全部保留。

完成后的界面应明显继承参考图的连续面板、灰紫选中态、克制图标和清晰预览层级，但不得照搬参考图中与已确认产品行为冲突的键盘提示、关闭按钮或自动复制行为。

## 3. 证据优先级

执行时按以下顺序解决冲突，后一层不能推翻前一层：

1. 已确认的产品意图
   - Alt+V 呼出或切换。
   - Esc 主动隐藏到托盘。
   - 点击其他软件不隐藏。
   - 面板置顶。
   - 鼠标点击选中。
   - 明确复制按钮写回剪贴板。
   - Enter、Ctrl+Enter、上下键不触发复制或选择。
2. 当前已经通过测试或真实验证的运行不变量
   - 窗口化几何提交使用稳定身份、revision 和 checksum。
   - 列表只接收受限摘要和缩略图，不接收完整正文或原图。
   - 复制、收藏、删除在 UI 线程冻结 ID 与内容哈希后才异步执行。
   - 搜索和历史结果使用代次隔离迟到事件。
   - 图片缩略图和纹理缓存有界。
3. 已确认视觉参考
   - 中性深色连续外框。
   - 搜索、筛选、历史和预览位于同一视觉容器。
   - 左侧列表、右侧预览。
   - 低饱和灰紫选中态和浅灰紫主按钮。
   - 圆润、克制的小图标。

若参考图显示“↑↓ 选择 · Enter 复制”、自定义关闭按钮或其他冲突元素，必须忽略这些元素，并在提交说明中记录“按产品意图保留现有行为”。

## 4. 当前实现事实

后续模型不得在未核对代码的情况下重新猜测以下事实：

- ui/app-window.slint 目前约一千行，包含根窗口、搜索、筛选、清空确认、两套列表渲染路径、状态和页脚。
- 当前窗口逻辑尺寸是 560×640；根窗口使用原生 Windows 标题栏，标题栏图标已经修复。
- 当前生产路径使用 geometry-mode：Rust 计算精确 prefix-sum 和最多 100 行的 WindowCommit，Slint 使用普通 Flickable 绝对定位有界窗口卡片。
- legacy ListView 仍用于旧 set_cards 测试和兼容路径。重设计期间不能在没有迁移证据时直接删除。
- 当前文本外层行高为 106，图片外层行高为 186；高度同时出现在 Slint、src/app/ui_event.rs 和若干几何/性能测试中。
- 当前 history-model-length 在 geometry 模式实际返回完整逻辑数量，与“实际绑定模型行数”的注释不一致。UIR-04 必须把完整逻辑数量和实际绑定的最多 100 行明确拆成两个只读属性。
- UiClipboardItem 只携带 id、最多 512 个 Unicode 标量的 preview、source、relative_time、content_hash、copy_count、is_pinned 和图片轻量元数据。
- 完整文本和图片原始文件不进入 UI DTO；复制时由后台按稳定 ID 和哈希读取完整载荷。
- 右侧内容预览第一版必须复用受限 preview 和现有 thumbnail。不得为“显示全文”新增 SQLite 迁移、同步读取完整正文或在 UI 线程解码原图。
- 当前每条历史卡片包含删除、收藏、复制按钮；目标界面会把这些操作迁移到右侧选中项操作栏。
- 当前 Slint 根组件仍捕获上下键并发送 selection-move-requested；用户已明确要求移除。
- 当前原生关闭请求被拒绝，Esc 通过面板代次隐藏；失焦不会自动隐藏；这些行为必须保留。
- 当前字体参考资产是 WOFF/WOFF2。项目使用的 Slint 编译链只把 TTF、TTC、OTF 识别为可导入字体，不能直接把现有 WOFF/WOFF2 当作 Slint 字体文件。
- 四个寒蝉圆黑体 WOFF 合计约 30MB。盲目嵌入会与轻量目标冲突。

## 6. 字体交付决定

本轮采用系统字体回退，不打包 design 目录中的字体：

- 中文正文和界面文字优先使用 Microsoft YaHei UI；若目标系统不可用，由 Slint/Windows 使用系统默认无衬线字体。
- 英文和数字保持同一系统字体链，避免为了脚本分流增加运行时逻辑。
- 用字重、字号、行高和字距继承参考图的气质：正文轻、按钮常规、标题中等、极少使用粗体。
- design 目录中的寒蝉圆黑体和 Public Sans 继续作为视觉参考与后续字体评估输入。

这是有意的轻量化决策，不是遗漏。若未来用户明确要求精确字体，必须另建独立字体交付计划，取得可由 Slint 直接使用的 TTF/OTF，核对 OFL 和保留字体名称，测量安装包及工作集增量后再决定；不得在本计划执行途中自行扩大范围。

## 8. 跨原子不变量

以下不变量从 UIR-01 到 UIR-18 始终成立：

1. UI 模型不接收完整剪贴板正文、HTML、原图字节、数据库错误详情、源窗口标题或敏感日志。
2. 文本列表和右侧文本预览只使用 UiClipboardItem.preview；复制仍按稳定 ID 和 content_hash 在后台读取完整载荷。
3. 图片列表和右侧图片预览只使用已有 thumbnail；列表使用 cover，预览使用 contain；不在 UI 线程解码原图。
4. 用户操作的身份在 UI 线程同步冻结为 panel_generation、id 和 content_hash；直接来自窗口化历史项的操作还必须通过当前 WindowCommit 身份校验，右侧操作栏则必须从完整快照的当前 selected_index 冻结身份，不能把 absolute index 当成 window local index。
5. WindowCommit 的 session nonce、dataset revision、window revision、commit revision、checksum 和最多 100 行上限不改变。
6. geometry-mode 与 legacy ListView 互斥占位；隐藏分支的高度、伸展和回调必须为零或被抑制，不能再次制造首屏空白。
7. 完整逻辑数量和实际绑定模型长度必须分离：geometry 模式前者可为 20,000，后者只能是 window-cards.length 且不超过 100；顶部数量、空状态和性能证据不能复用同一个含糊属性。
8. 文本和图片的行高各只有一个 Rust 常量来源，并与 Slint 外层行高和所有几何测试完全一致。
9. 新复制记录到达时没有伪造占位项；列表第一项就是最新摘要，第二项不被第一项覆盖。
10. 卡片点击只改变选择；点击卡片空白、摘要、来源或缩略图均选择同一项。
11. 历史项本身不再放置收藏、删除、复制按钮；所有内容操作位于右侧选中项操作栏。
12. Enter 和 Ctrl+Enter 只被静默消费，不复制、不粘贴、不关闭；上下键不改变选择；Esc 隐藏当前代次面板。
13. 点击其他应用不隐藏面板；标题栏关闭仍不退出；托盘退出仍是唯一正常退出入口。
14. 搜索防抖仍为 120ms，旧搜索结果和迟到事件仍被代次拒绝。
15. 全部、文本、图片、收藏的索引和 SearchFilter 映射不变。
16. 收藏、删除、清空未收藏、清空全部的 pending、失败回滚、强确认和互斥规则不变。
17. 滚动接近底部的续页门禁、失败后手动重试、追加锚点和缩略图 LRU 仍有界。
18. 日志不记录 clipboard preview、完整正文或原图路径详情。
19. 不修改 design 目录，不将字体 WOFF/WOFF2、参考图或用户临时截图纳入本轮提交。

统一空历史、搜索中、无结果、搜索失败、加载更多、续页失败、收藏/删除/清理失败和开机启动反馈的位置，消除状态出现时列表跳动、首项下移或被覆盖。

#### 前置条件

- UIR-14 已完成。
- 所有状态仍由现有 Rust 属性驱动。

#### 允许修改

- ui/components/preview-pane.slint、cleanup-panel.slint 和 history-row.slint 的状态视觉。
- ui/app-window.slint 的左栏固定状态区、空状态覆盖层和全局短反馈。
- tests/ui_shell_contract.rs、tests/history_scroll.rs、tests/selected_preview_contract.rs。
- 新增 tests/ui_status_contract.rs。
- 本计划台账。

#### 禁止修改

- 不修改搜索、分页、mutation 和 startup 状态机。
- 不把错误详情、路径、SQL 或剪贴板正文传进 UI。
- 不用伪造 ClipboardCard 表示空状态或 loading。
- 不让状态组件参与 history geometry prefix。

#### 实现步骤

1. 左栏底部保留固定 34px 状态行：正常时显示“Esc 关闭到托盘”和清理入口；加载更多显示“正在加载更多…”；续页失败显示可点击“加载失败，点击重试”。
2. 空历史、搜索 empty、搜索 loading 和首页 error 在列表视口上方使用覆盖层，不创建模型项、不改变 viewport-height。空历史判断统一使用 history-active-logical-count == 0，不能使用仅表示实际绑定行数的 history-model-length，也不能直接读取 window-cards.length。
3. 右侧无选择状态位于预览体中心；选择存在后完全隐藏，不能残留在真实内容上层。
4. pin/delete/clear 的固定错误文案放在操作栏上方固定高度的小状态位，默认透明占位或同尺寸替换，不能挤压预览体。
5. startup-status 放在工具栏或固定状态区，不单独插入 VerticalLayout 行；文字过长单行 clip。
6. 加入状态组合优先级，至少为：强确认遮罩 > mutation pending/error > 续页失败/loading > 搜索状态 > 正常。无关状态不能同时叠在同一位置。
7. 构造启动空历史、1 条、30 条、追加中、搜索空、失败和新捕获首项场景，比较首项 top 与 history-visible-height 均稳定。

#### 必须保持的边界

- 空状态不增加 history-active-logical-count 或 history-model-length；前者保持真实逻辑数量，后者保持真实绑定数量。
- retry 只有 history-retry-required=true 时 enabled。
- 首页搜索 error 保留旧卡片的现有规则不变。
- 新捕获插到顶部时不出现空白代理，原首项成为第二项且无覆盖。

    cargo test --lib 首页查询失败保留旧卡片 -- --test-threads=1
    git diff --check

#### 完成标准

- 所有状态都有唯一位置和明确优先级。
- 状态变化不改变列表视口高度或首项 top。
- 初始空历史没有空白卡片，新复制没有覆盖。

- 风险 L1，不需要 DDD；若实现修改 reducer 状态优先级则自动升级为 L2 并执行 DDD。

### UIR-16：DPI、长文本与可访问性收口

#### 单一目标

## 12. L2 原子的 DDD 复核协议

DDD 必须使用隔离上下文，不能让复核者继承“实现一定正确”的叙事。给复核者的输入只包含：

- 当前原子的完整任务契约。
- 基线提交与当前 diff。
- 直接相关文件。
- 已执行的定向测试和原始通过/失败摘要。
- 明确不变量和禁止范围。

复核者必须输出：

1. 阻塞发现：会导致错误记录操作、数据丢失、几何错位、无界内存、核心交互回归或验收伪阳性的事项。
2. 非阻塞建议：可读性或未来维护建议，不得借此扩大本原子。
3. 被测试证明的内容。
4. 只能靠代码推理或真实 Windows 验证的内容。
5. 结论：通过、修复后通过、需要重规划。

执行模型处理规则：

- 有阻塞发现：修复、重跑定向测试、再次隔离复核，未通过不得提交。
- 只有非阻塞建议：记录到原子结果；仅在允许文件且不扩大范围时处理。
- 复核要求实现排除功能：以本文范围为准拒绝扩大。
- DDD 不运行全量测试，也不代替测试。

- 第一项新增后旧第一项成为第二项。
- 选中项位于当前 WindowCommit 外。
- 20,000 项性能数据：10,000 文本、10,000 图片。

### 13.4 测试禁止

- 不用 source.contains 作为所有行为的唯一证据；危险回调、点击和状态必须真实触发测试后端事件。
- 不因 UI 坐标变化只修改坐标而不验证点击命中了哪个稳定身份。
- 不把 ignored 测试返回码 0 当作测试通过；必须看到实际 passed 数大于 0。
- 所有带名称过滤器的 cargo test 命令都必须把原始 passed 数量回写台账；passed=0 即失败，即使进程退出码为 0。
- 不删除失败测试来适配新设计。
- 不执行 cargo clean 或全量 cargo test。

## 14. Git 与工作区规则

1. 开始每个原子前执行 git status --short --branch。
2. design、target、临时截图、数据库和日志不得暂存。
3. 只用显式路径 git add；禁止 git add . 和 git add -A。
4. 每原子一个提交，提交标题采用本原子给出的建议标题。
5. 提交正文至少写：
   - 用户可见变化。
   - 保持的不变量。
   - 定向测试。
   - DDD 结论（L2）。
6. 提交后把短 SHA 回写执行台账。
7. 若执行会话明确授权远端同步，确认 origin 指向预期仓库后推送当前分支；否则只本地提交。
8. 不为本计划执行创建远端 worktree 分支。若因其他明确要求使用本地 worktree，仍禁止并行修改相同 UI 热点文件。

## 16. 全计划停止条件

出现以下任一情况时，把当前原子改为 blocked，记录证据并停止，不得自行扩大范围：

- 当前分支缺少创建基线后的关键功能，计划定位与代码不再匹配。
- design 用户资产被其他任务修改或暂存，无法安全隔离。
- 必须修改 SQLite schema、完整载荷边界、图片原图路径或剪贴板核心协议才能继续。
- WindowCommit 身份、checksum 或几何上限需要被削弱。
- 同一阻塞在一次实现、一次针对性修复和一次 DDD 后仍出现。
- 需要新的产品选择，例如必须精确使用自定义字体、必须支持单栏小屏或必须改变 Esc/Alt+V 行为。

普通编译错误、测试夹具坐标变化、局部 Slint 语法问题或一次性能抖动不构成全计划 blocker；先在当前原子范围内修复并重测。
