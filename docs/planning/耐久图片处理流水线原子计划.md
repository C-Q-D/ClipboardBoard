## 总体计划

### 产品交付单元

本计划实现 `UNIT-10 / ATOM-35`：ImageWorker 接收已脱离剪贴板句柄的 PNG 或 DIB
拥有型输入，解码为规范像素，生成耐久 PNG 原图和最长边 320px 的 WebP 缩略图，
通过独占 staging 文件发布到已准备图片根。

### 目标结果

- 注册 PNG 优先于 DIBV5/DIB；同一请求只处理一种编码输入。
- ImageWorker 不持有 HGLOBAL、HBITMAP、SQLite 连接或 Slint Image。
- 原图 PNG 与缩略图 WebP 先写独占 staging，flush、sync、关闭后才重命名发布。
- 可观察发布失败只回滚本次调用实际创建的正式文件，不删除既存资产。
- ImageWorker 发布后等待 ATOM-36 的 commit/rollback ACK，ACK 前不处理下一图片请求。

### 验收场景

1. 规范 RGBA8 编码为可解码 PNG，像素与 alpha 不变。
2. 最长边大于 320px 时保持比例缩小；两个维度均不超过 320；小图不放大。
3. 缩略图为可解码的 lossless WebP。
4. 两份 staging 文件均为本次捕获独占，编码失败不产生正式文件。
5. 第二份发布失败时尽力回滚本次新发布的第一份；回滚失败返回独立错误分类。
6. 成功后两份正式文件非空且元数据路径、尺寸、内容哈希和原图大小一致。
7. ImageWorker 容量一 latest-wins；停止后拒绝请求并 join；结果不泄漏图片字节到 Debug。
8. PNG、DIBV5、DIB 输入分别走已提交解码器；解码或文件错误返回稳定分类。
9. metadata 尚未成功交付时响应端断开，worker 可确定数据库不可能提交并回滚；交付后
   finalize 断开或 stop 属于未知状态，必须保留资产并标记 `FinalizeAbandoned`。

### 明确排除

- 不修改 `ClipboardIoWorker` 当前文本捕获 DTO；格式读取到 ImageWorker 的生产接线留给
  ATOM-36 与历史事务一起完成，并同步扩展 ATOM-36 的允许范围。
- 不写 SQLite，不更新 UI，不创建 Slint Image。
- 不做图片复制回系统剪贴板。
- 不做自定义目录设置 UI、旧资产迁移、缓存清理或崩溃启动对账。
- 不支持损坏既存正式资产的自动修复；发现不完整资产时稳定失败并留给后续对账。

### 跨原子不变量

- 编码输入采用 `RegisteredPng`、`DibV5`、`Dib` 三种拥有型枚举；优先选择函数固定
  PNG > DIBV5 > DIB。
- 规范像素和编码字节的 Debug 均只输出类型、尺寸或长度，不输出内容。
- PIPE-01 再次检查输入 RGBA 长度不超过 64 MiB。缩略图长边为
  `min(320, input_long)`；短边使用
  `max(1, floor(input_short × target_long / input_long))`，全部通过 `u64::checked_mul`
  计算，两个输出维度均不得大于输入或 320。
- WebP 缩略图额外 RGBA 缓冲最多 `320 × 320 × 4` 字节；writer API 不持有第二份完整
  编码 Vec，但允许编码器使用其有界内部缓冲。
- PNG 与 WebP 编码直接写入调用方 writer，不在 API 中强制保留第二份完整编码 Vec。
- 耐久原图固定 `MAX_PERSISTED_PNG_BYTES = 80 MiB`，独立于剪贴板注册 PNG 的
  30 MiB 输入上限。PNG writer 包装计数/限长 writer，超过持久化上限立即失败。
- 持久化 PNG 验证使用独立 policy：编码文件不超过 80 MiB，尺寸不超过 16384，
  解码 RGBA8 不超过 64 MiB；不得调用 `decode_registered_png` 的 30 MiB policy。
- staging 文件名包含进程实例 nonce、进程 ID 和全局单调 token；仍以 `create_new`
  作为唯一防覆盖保证，碰撞时推进全局 token 并有界重试。
- staging 与正式目录位于同一图片资产根，发布使用同卷 rename。
- 固定阶段为：创建两份独占 staging → 编码两份 → 分别 flush/sync/drop → 两份均成功
  后才开始 rename。任一编码或同步错误只清理本次 staging，不产生正式文件。
- `PreparedImageStorage` 增加窄的 crate-private 安全发布 capability；创建或复用哈希
  分片目录时使用 Windows guard 拒绝 reparse point，PIPE-02 不依赖未校验裸路径写入。
- 两份正式文件完整存在时才幂等复用；只有一份存在时拒绝，不猜测所有权。
- 发布顺序为原图、缩略图；缩略图发布失败时只删除本次刚发布的原图。
- PIPE-02 消费拥有型 `CanonicalImagePixels`。完成哈希、目标缩略图和两份 staging
  编码后，只保留哈希、尺寸与最多 320px 预期缩略图，先 drop 原始 64 MiB 像素，再
  解码正式原图执行验证；既存复用也在验证前释放原始大像素。
- 新发布和既存复用使用相同验证：两份均为普通非空文件；原图按持久化 policy 可解码且规范哈希、宽高
  与路径哈希一致；lossless WebP 解码后的 RGBA 必须与确定性缩放结果逐字节相同。
  目标已存在时不得覆盖，重新走完整资产验证；其他 rename 错误稳定失败。
- 两次 rename 不是跨文件原子事务。函数可观察错误路径尽力回滚；进程在两次 rename
  之间终止可能留下单边资产，本原子识别并拒绝，ATOM-49 负责启动对账最终收敛。
- 回滚删除失败返回 `RollbackIncomplete`，不得伪装成普通发布失败。
- ImageWorker 只持有不可克隆的 `PreparedImageStorage`，请求槽容量一、结果按请求返回。
  输入字段私有并通过 smart constructor 在入队前检查 PNG 30 MiB、DIB 72 MiB 上限；
  替换 pending 时立即 drop 旧字节。像素解码/编码阶段最多一份 64 MiB 规范像素；
  post-verify 前已经 drop 该像素，再产生至多一份 64 MiB 验证像素。另有一份在途编码、
  一份 pending 编码、最多 320px 缩略图和编码器有界内部缓冲。
- worker 发布后把只读 metadata 交给调用方，但继续独占本次创建所有权并等待单次
  finalize 命令；finalize handle 的 `commit()/rollback()` 各携带一次性 completion
  通道。commit completion 确认 worker 已释放所有权；rollback completion 返回成功或
  `RollbackIncomplete`。worker 一旦收到显式 commit/rollback 就必须执行；completion
  receiver 断开只表示调用方未观察结果，不能撤销或改判 finalize 决策。
- metadata 交付前 response send 失败时可自动回滚。metadata 交付后、尚未收到
  finalize 命令时，finalize sender 断开或 stop 到达属于未知状态：保留资产、标记
  `FinalizeAbandoned` 并释放 worker 等待，绝不隐式删除可能已被数据库引用的文件。
- finalize 等待使用有界 `recv_timeout` 并同时观察 worker stop 信号，不得让 stop
  永久阻塞。正常关闭顺序固定为：停止新 ClipboardIO 图片输入 → 排空数据库事务并完成
  finalize → stop ImageWorker。
- 移动 `PreparedImageStorage` 前提取只读根注册快照：root ID、root kind、规范路径；
  ATOM-36 用该快照在同一存储事务注册资产根。

### 原子依赖顺序

1. `PIPE-01`：PNG/WebP 编码与缩略图尺寸。
2. `PIPE-02`：独占 staging、原子发布、回滚和元数据。

## PIPE-03 ImageWorker 有界处理

- 状态：in_progress
- 唯一目标：用独立线程串行解码并发布 PNG/DIB 输入，不阻塞 ClipboardIO 或 UI。
- 允许修改：ImageWorker 模块、格式输入 DTO、定向并发测试、计划状态。
- 明确不修改：当前 ClipboardIoWorker、StorageExecutor、历史桥、UI。
- 实现契约：
  - 输入枚举字段私有，只能经 30/72 MiB smart constructor 建立；Debug 只输出格式与长度。
  - 选择 helper 固定 PNG > DIBV5 > DIB。
  - 请求槽容量一且 latest-wins；被替换请求的响应端断开。
  - worker 独占 `PreparedImageStorage`，先解码再调用 PIPE-02。
  - 发布结果携带 finalize handle；commit/rollback 命令带 completion 回执。命令一旦被
    worker 接收就执行；completion 发送失败不改变 commit/rollback 事实。
  - 响应 send 失败时取回发布结果并回滚；交付后的 finalize 断开或 stop 保留资产并
    标记 `FinalizeAbandoned`。finalize 等待以超时轮询 stop，不能永久阻塞 join。
  - stop 关闭入口、丢弃未开始请求；正常生产关闭先排空数据库 finalize，再 stop worker。
  - start 返回根注册快照，供 ATOM-36 注册当前 root ID、kind 和 canonical path。
- 测试：三格式、优先级、输入超限、latest-wins、解码/发布失败、metadata 接收端提前
  断开自动回滚、finalize commit/rollback completion、rollback 不完整、completion
  receiver 断开后 commit 仍保留、rollback 仍删除、finalize sender 断开保留、
  sender 存活不发送时 stop 可 join 且保留、
  Debug 脱敏。
- 完成判定：定向验证和 L3 DDD `PASS`。
- 计划提交：`feat(image): [PIPE-03] 建立有界 ImageWorker`
