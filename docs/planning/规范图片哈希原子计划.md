## 总体计划

### 产品交付单元

本计划实现 `UNIT-10 / ATOM-31`，为 PNG、DIB、DIBV5 和后续 `CF_BITMAP`
解码结果提供唯一的规范像素载荷与图片内容哈希契约。

### 目标结果

- 领域层拥有一份顶向下、行连续的 RGBA8 像素载荷。
- 构造时拒绝零尺寸、尺寸乘法溢出和长度不匹配。
- BLAKE3 输入固定为域标签、宽度小端字节、高度小端字节和全部 RGBA 字节。
- 相同规范像素不受来源编码元数据影响，得到同一 32 字节内容哈希。

### 验收场景

1. 精确长度的非零 RGBA8 载荷可以构造，并只暴露只读尺寸、字节和哈希。
2. 零宽、零高、尺寸乘法溢出、短一个字节和长一个字节均返回稳定错误。
3. 固定 1×1 输入得到固化 golden digest，锁定域标签结尾 NUL、字段顺序和
   `u32` little-endian 编码。
4. 修改像素、在相同字节下交换 2×1 与 1×2 尺寸，或交换内容不同的两行，
   均改变哈希输入，并在定向样例中得到不同哈希。

### 明确排除

- 不读取 Windows 剪贴板。
- 不解码 PNG、DIB、DIBV5 或 `CF_BITMAP`。
- 不负责 stride、BGRA、行方向、预乘 alpha 或色彩空间转换。
- 不写图片文件、SQLite、UI、日志或设置。
- 不修改 PERSIST-02 图片元数据和 PERSIST-03/04 路径目录契约。

### 已确认架构与代码接缝

- `src/domain/hash.rs` 已建立文本的域分隔 BLAKE3 模式。
- `src/domain/image_metadata.rs` 接收 `[u8; 32]` 图片哈希并绑定相对路径。
- `src/domain/mod.rs` 是领域类型的统一导出入口。
- `ATOM-32/33` 分别负责 PNG 与 DIB/DIBV5 的来源解码和规范化。

### 跨原子不变量

- 规范像素对象拥有 `Box<[u8]>`；宽、高、像素字段私有。
- 公共接口不提供可变像素访问或绕过校验的构造方式。
- 构造函数只机械验证非零尺寸、`width × height × 4` 和长度；调用方负责声明输入
  已经是顶向下、行连续、straight RGBA8。
- 哈希协议版本变化必须显式迁移，不能静默修改域标签、字段顺序或整数编码。
- 代码、测试和计划必须使用中文职责与边界注释。

## ATOM-31 定义规范图片哈希

- 状态：in_progress
- 支持的验收场景：场景 1 至 4。
- 唯一目标：把调用方已规范化的 RGBA8 像素封装为不可失效的领域对象，并计算稳定
  图片内容哈希。
- 当前行为与目标行为：当前图片元数据只能接收外部哈希；完成后领域层可验证规范
  像素形状并生成该哈希。
- 前置条件与依赖：ATOM-30 已提交；工作区基线为 `20408d7`。
- 代码定位依据：`src/domain/hash.rs`、`src/domain/image_metadata.rs` 和
  `src/domain/mod.rs`。
- 允许修改：新图片内容领域模块、领域导出、模块定向测试、中文注释门禁、计划和
  项目状态。
- 明确不修改：剪贴板读取、图片解码转换、磁盘目录、SQLite、UI 和依赖配置。
- 实现步骤：
  1. 定义 `CANONICAL_IMAGE_HASH_DOMAIN` 和稳定错误枚举。
  2. 定义字段私有、拥有像素缓冲区的 `CanonicalImagePixels`。
  3. 用 checked arithmetic 验证非零尺寸与 `width × height × 4` 精确长度。
  4. 按域标签、宽高小端字节、RGBA 字节顺序计算 BLAKE3。
  5. 仅公开只读尺寸、只读字节视图和内容哈希。
- 接口、数据与错误契约：构造参数为 `u32` 宽高和 `Vec<u8>`；失败区分零尺寸、
  尺寸溢出和像素长度不匹配；错误和 Debug 不输出像素内容。
- 边界与异常：构造无法判断预乘 alpha、通道含义或来源行方向，公共文档必须明确
  这些由调用方保证；哈希只对已经规范化的载荷成立。
- 测试要求：精确长度成功；零宽、零高、乘法溢出、过短、过长拒绝；1×1 golden
  digest；相同内容稳定；像素、尺寸和不同内容行交换样例不同。
- 验证命令：`cargo test domain::image_content::tests --lib`；
  `cargo check --lib`；`cargo clippy --lib -- -D warnings`；
  `cargo test --test comment_policy`；`scripts/check_comments.ps1`；`git diff --check`。
- 预期结果：调用方无法构造或维持形状无效的规范像素对象，哈希协议由 golden 测试锁定。
- 完成判定：全部定向验证通过，完整 diff 经 L2 DDD 返回 `PASS`。
- 交付给下一原子的输出：ATOM-32/33 可消费的规范像素 DTO 与图片内容哈希。
- 停止或重新规划条件：后续解码器需要不同的拥有权模型才能避免不可接受的整图复制。
- 风险等级：L2
- DDD 门禁：计划已在三轮修订后 `PASS`；提交前复核不变量和哈希协议。
- 计划提交信息：`feat(image): [ATOM-31] 定义规范图片内容哈希`
